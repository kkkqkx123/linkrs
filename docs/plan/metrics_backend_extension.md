# 指标后端扩展方案（第一阶段先行）

本文给出后端指标补齐与聚合接口的修改方案，是整个指标工作的第一阶段。前端集成单独见同目录另一篇文档，等待本阶段完成后实施。

## 1. 背景与现状

采集层 `graphdb-metrics` 已有约 130 种 `MetricType`、分阶段 `QueryMetrics`、详细 `QueryProfile`、直方图、错误统计、聚合模式统计、慢查询日志，但暴露层只用了其中一小部分。

当前 `graphdb-server/http/handlers/statistics.rs` 的五个接口存在缺口：系统接口只有整机 CPU 均值、内存、连接数；数据库接口的缓存命中率写死为零，QPS 用最近 100 条时间跨度估算；查询接口的起止时间参数未实际过滤，只有慢查询前十；图查询没有百分位，只有搜索有；存储、事务、检查点、脏页、碎片、墓碑、Bloom 等已采集计数器没有统一出口。查询响应 `QueryMetadata` 只有总耗时与扫描行数，分阶段耗时与追踪编号下不来。

## 2. 目标与非目标

目标：把已采集的数据以稳定结构暴露出去，让前端一个聚合接口加若干明细接口就能画出资源、查询、存储全景；修正现有明显失真字段；查询链路下发分阶段耗时与追踪编号。

非目标：不做分布式追踪，不做告警规则引擎，不做 Prometheus exposition 格式，不做长期时序落盘，不引入新的后台采样线程，不新增替代模块。

## 3. 约束

依赖方向保持现有 DAG：采集在 `graphdb-metrics`，传输结构在 `graphdb-wire`，组装与 HTTP 在 `graphdb-server`。所有改动直接修改原模块与原 handler 函数，不新建替代模块，不做版本升级，不保留兼容分支。统计口径保持近似求和，在文档中写明。验证合并为尽量少的编译与测试批次。

## 4. 总体设计

分三层推进：采集层补读接口与快照组装，传输层补字段与响应结构，服务层补 handler 逻辑与配置。路由保持 `/v1` 前缀不变，在原有统计路由上扩展响应字段，并新增一个聚合概览路由与一个明细查询画像路由，避免前端多次往返。配置沿用 `graphdb-config/monitoring` 节扩展，不新增配置文件。

## 5. 采集层改造

位置：`crates/graphdb-metrics` 原有文件内修改。

时序采样：在 `StatsManager` 内部增加固定长度环形缓冲，记录每秒粒度的查询数、均值延迟、错误数，以及资源采样点。写入由现有记录路径触发，读取提供按窗口取序列的方法。容量与保留窗口走配置，不写死。

图查询百分位：复用已有的查询延迟直方图读方法，将均值与分位置信区间通过新的快照方法一次性返回，供查询接口使用，不另起直方图实现。

错误与模式：将已有的错误摘要、近期错误、聚合模式前若干、执行器汇总的读能力整理为面向 handler 的快照方法，返回调用方直接可序列化的聚合结果，避免 handler 逐个拼计数器。

存储与事务快照：增加按子系统组装快照的方法，把存储读写次数与延迟均值、索引内存、墓碑计数与内存、碎片千分比与浪费字节、Bloom 查询与命中率、检查点成功失败与触发原因、迁移计数、事务结果与资源水位一次性取出。脏页与增量检查点策略计数同样纳入存储快照。

## 6. 传输结构改造

位置：`crates/graphdb-wire` 原有查询与统计相关模块内修改。

查询元数据扩展：在 `QueryMetadata` 上以带默认值可选字段形式追加追踪编号与分阶段耗时、计划节点数、结果行数。全部可选且默认缺省，老客户端不受影响。查询、批量、流式、游标四条路径共用同一结构。

统计响应结构化：将目前 handler 直接拼 `serde_json::Value` 的做法收敛为 wire 中的具名响应结构，至少覆盖系统资源、数据库概览、查询统计、搜索统计四块。字段命名与现有 JSON 键保持一致，只做增量追加，避免前端已解析字段改名。

## 7. 服务层改造

位置：`crates/graphdb-server/http/handlers` 原有文件内修改，不新增 handler 模块。

系统资源接口：在原 `system` 函数内修正 CPU 采样为两次采样取差，不再单次刷新即读；区分进程内存与整机内存，追加进程启动时长、数据目录磁盘用量、预写日志目录大小、最大文件描述词配置。连接统计保持现有语义。

数据库接口：在原 `database` 函数内修正缓存命中率硬编码，改为真实搜索缓存命中率或明确标注未支持；QPS 改为复用聚合统计的当前秒计数，不再用最近百条时间跨度估算；性能段追加图查询百分位与错误总数；存储段追加碎片、墓碑、脏页、检查点摘要；搜索段保持现有字段。

查询接口：在原 `queries` 函数内实现起止时间过滤，未传则默认近一小时；返回追加错误按类型与按阶段汇总、聚合模式前若干（含执行次数、均值、九十五与九十九分位、错误率）、执行器类型汇总。慢查询列表保留现有形状，追加追踪编号与阶段耗时。

搜索接口：保持现有字段，追加按索引维度的操作与延迟分解已有的计数能力，不新增存储。

聚合概览与画像明细：在原 `statistics.rs` 内新增两个函数，一个返回跨系统、查询、存储、事务、同步的概览快照供监控页首屏使用，一个按追踪编号返回单次查询画像明细供控制台跳转。路由在原 `router.rs` 统计分组内注册，注解在原 `openapi.rs` 统计分组内登记。

查询执行链路：在 `query.rs` 的响应组装处把引擎侧已有的分阶段耗时与追踪编号填入扩展后的元数据；流式与游标路径同样在结束元数据中携带。失败路径同样记录错误画像，保证错误统计不漏。

## 8. 存储与同步打通

存储统计保持 `StorageStats` 语义不变，handler 侧追加对其的补充说明注释。冻结统计保持现有形状。检查点、脏页、碎片、墓碑、Bloom 的取值全部走采集层新增的快照方法，不在 handler 内重复计算。事务指标接口保持现有形状，字段与采集层事务快照对齐。同步状态接口保持现有形状，概览接口直接复用其返回值做聚合，不改同步逻辑。

## 9. 配置与文档

在 `graphdb-config/monitoring` 原结构内追加画像缓存大小、直方图样本上限、时序保留窗口、资源采样间隔，均给安全默认值并加入校验。慢查询阈值沿用现有字段，不另起配置项。接口变更后按仓库既有流程刷新 `frontend/openapi.json` 快照，保证契约测试通过。统计口径说明随接口文档更新。

## 10. 测试与验收

单元层面覆盖新增快照方法的空数据、满缓冲淘汰、百分位单调性、错误汇总求和。接口层面覆盖概览与明细的正常返回、空库返回零值不报错、起止时间过滤生效、追踪编号不存在返回未找到。验收以一次全量编译加一次目标包测试为基准，不单独为每个小改动起编译批次。

## 11. 实施顺序

先做采集层快照与传输结构扩展，再做系统与数据库接口修正，然后做查询与搜索接口扩展与画像下发，接着做聚合概览与明细路由与配置，最后统一刷新契约与文档。前一步是后一步的前置依赖，不并行。
