# 向量后端一致性整改方案

配套分析见此前对同步包是否仅针对远程存储的分析结论。
本文只描述本次落地的改动与远期方向，不贴完整代码。

## 结论前置

同步包不是仅针对远程存储，而是派生二级索引的统一协调层。
全文检索本地可用，向量检索本地与远端共用同一条投递链：
事务暂存、持久化发件箱物化、认领应用确认、重试死信、重建发布。
远端只是向量后端的一个分支，差异应当收敛在后端抽象内，
投递与重建不应再按本地或远端分叉。

## 本次范围

本次只落地向量后端抽象内部的三处整改，一次完成。
三处同属同一抽象的不同切面，合并为一次代码修改与一次编译验证。
不新增替代模块，只改原模块。不拆分大结构，远期拆分另议。

## 改动一：分组批量写入下沉到后端

现状：协调器的批量投递对本地有专用快道，直接拿出底层引擎做分组提交，
而通用路径先由索引管理器分组再逐集合调用写入。
两处做相同的载荷转换与分组，转换逻辑重复，新增后端要改分发点。

改法：分组转换仍由索引管理器负责，保持单一转换点。
后端抽象新增一个分组批量写入操作，接受已分组的写入与删除集合。
本地实现用底层引擎的分组提交能力，保证同批多集合的确定性顺序。
远端实现沿用现有的逐集合写入语义，保持并发与批量策略不变。
协调器只做分组加一次后端调用，不再判断本地或远端，
也不再直接触碰底层引擎。

验收：协调器内无本地判断与底层引擎直接调用，
分组转换只有索引管理器一处，本地多集合顺序语义不变，
远端写入语义与性能不变。

## 改动二：原子发布能力显式化

现状：后端接口承诺了本地才有的原子改名式发布语义，
远端实现只能返回不支持的错误，调用方靠试错或按名称分支来区分。
重建的修复与重采用路径也按本地或远端名称分支，
能力信息藏在名称判断里。

改法：在后端抽象上新增原子发布能力查询，本地肯定回答，
远端否定回答，指标装饰器直接透传。
索引管理器的发布与回退选择按能力查询分支，不再按名称分支。
重建的中断修复只在具备原子发布能力的后端上尝试改名修复，
远端走逻辑指针重采用路径，不再先调一个注定失败的方法再兜底。

验收：远端不再出现预期内的不支持错误，
发布与恢复的选择由能力查询驱动，接口语义与行为不变。

## 改动三：滚动扫描真流式化

现状：两后端的滚动流实现都是先全量分页拉取到内存再转成流，
名字是流，行为是物化。大集合下内存随数据量线性增长，
与流式预期的常数内存相悖。检索流受限于检索接口本身无分页，
全量缓冲不可避免，应当如实说明。

改法：滚动流改为按需分页拉取的真流，
内部状态只保留游标、少量缓冲与结束标志，
每次只在缓冲耗尽时拉下一页，空页跳过，遇错则单条报错并结束。
检索流保持现有行为，但注释如实说明其缓冲加转发的本质，
不再暗示其为增量远端流。

验收：滚动流不再有全量收集容器，
空页与尾页行为不变，错误只影响当前条目后的终止语义。

## 执行顺序

三处同时落地。分组写入先行定义接口，
能力查询随后替换分支，滚动流最后替换实现。
同属后端抽象，一次修改一次验证。

## 验证方式

单次编译检查覆盖向量与远端特性组合，输出重定向到文件后阅读，
不再编译期内反复过滤。行为验收以现有向量后端测试与重建测试为准，
不新增大面积测试。

## 远期方向（本次不执行）

- 本地同步快道：纯单机部署下是否允许绕过持久化发件箱的同步直写，
  需存储、事务与查询层共同确认一致性语义后另议。
- 运行时桥接收敛：同步包内的阻塞桥接与各协调器自带运行时句柄的
  嵌套关系，需要统一的运行时归属说明。
- 管理器体量：同步管理器与发件箱的职责过大问题，
  按职责拆分需跨包协同，不在本次执行。
- 配置收敛：全文同步配置与向量投递策略分处两地，
  统一调优点需配置层参与。
