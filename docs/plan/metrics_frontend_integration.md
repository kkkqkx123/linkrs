# 指标前端集成方案（等待后端第一阶段完成后实施）

本文给出前端指标展示与交互的修改方案，依赖同目录后端扩展方案中的聚合概览、画像明细、元数据扩展接口先行落地。本阶段不改后端逻辑。

## 1. 背景与现状

前端当前只有三处指标触点：右上角健康面板请求 `GET /v1/health` 并自算往返延迟，数据浏览页请求空间统计展示顶点边数量，控制台展示单次执行总耗时。后端已有的数据库、系统、查询、搜索、事务、同步统计接口在前端没有任何服务封装，也没有监控页面。契约文件已生成这些路径的类型，但调用层缺失。

## 2. 目标与非目标

目标：新增一个监控页作为指标总览入口，升级健康面板与控制台结果展示，接通后端第一阶段提供的概览、系统、查询、存储、事务、同步接口，支持手动刷新与定时轮询、中英文、深浅色、加载与空与错误态。

非目标：不引入重型图表依赖，不做自定义告警配置页，不做多集群对比，不做日志文件浏览，不改现有查询执行主流程与鉴权流程。

## 3. 约束

复用现有 `openapi-fetch` 客户端与 `X-Session-ID` 注入、鉴权失效跳转、 envelopes 解析逻辑。路由沿用 `svelte-routing` 与 `ProtectedRoute`，样式沿用 Tailwind 与现有卡片风格。所有新增文案同时提供中英文。统计数字的单位换算集中在工具函数内处理，组件内不散落换算逻辑。

## 4. 总体设计

新增服务层、状态层、页面层三部分。服务层按后端资源分组封装请求，状态层负责轮询、缓存最近一次成功结果、错误保持旧值，页面层按概览、资源、查询、存储四组卡片展示，慢查询与画像明细用表格加抽屉。控制台与健康面板做增量增强，不重构现有页面结构。

## 5. 服务层改造

在 `frontend/src/lib/services` 内新增统计服务，按概览、系统、数据库、查询、搜索、事务、同步分组封装调用，全部走已有 `call` 与 `client` 方法，参数与后端契约保持一致。空间统计与健康检查保持现有服务不变，统计服务只新增不替换。查询服务在解析响应时透传后端新增的追踪编号与分阶段耗时字段，供控制台与画像抽屉使用，不改变现有成功失败判定。

## 6. 状态与轮询

新增监控状态存储，保存概览与各分组最近一次成功载荷、最后刷新时间、正在加载标记、错误信息。页面进入时拉取一次，之后按固定间隔轮询，间隔默认十秒并提供暂停开关。切出页面时停止轮询。单次刷新失败不清空旧数据，只展示错误提示条。手动刷新按钮与自动轮询共用同一拉取方法。

## 7. 页面与路由

在现有 `Sidebar` 导航内新增监控入口，在 `App` 路由表内注册监控页并置于 `MainLayout` 与鉴权守卫之内，主页的模块卡片区追加监控入口保持视觉一致。监控页布局按首屏概览卡、资源卡、查询卡、存储卡从上到下排列，表格类内容支持横向滚动。图表不引入新库，用现有样式实现条形分布与数值卡，趋势线用轻量可缩放矢量折线，数据来自后端时序序列字段。

具体展示分组为：服务状态与版本与运行时长与连接水位；处理器与内存与磁盘与日志目录用量；总量与活跃数与每秒查询与均值与分位延迟与错误汇总与慢查询前十；空间数与顶点边数与分配与存活与索引大小与碎片与墓碑与检查点摘要；事务结果与资源水位；同步与发件箱水位。缺失字段展示为横线，不用零填充误导。

慢查询表格行点击后请求画像明细接口，在抽屉内展示分阶段耗时、执行器明细、结果行数、错误信息，并提供按追踪编号复制与跳回控制台复现的能力。

## 8. 存量页面增强

健康面板在现有服务版本状态基础上追加进程内存、磁盘用量、活跃连接三行，数据来自系统与概览接口的缓存，失败时回退为现有三行。控制台结果头在总耗时旁追加分阶段耗时悬浮明细，批量结果每行同样支持展开。历史记录保留现有形状，追加追踪编号字段用于关联画像。

## 9. 国际化与样式

中英文词条在现有 `i18n` 目录内按监控命名空间追加，覆盖卡片标题、单位、刷新、暂停、空数据、加载失败、画像抽屉文案。深色模式沿用现有色板，表格与抽屉与控制台保持一致。数值格式化沿用现有时间与行数工具并新增字节与百分比换算。

## 10. 接口消费关系

监控页首屏依赖聚合概览接口，各分组卡片按需请求系统、数据库、查询、搜索接口，事务与同步卡片请求对应现状接口，画像抽屉请求画像明细接口，控制台增强消费查询响应元数据扩展字段。所有接口均等待后端第一阶段完成后联调，联调前先用契约类型做空态开发。

## 11. 测试与验收

前端校验用现有检查与构建流程覆盖类型与样式，路由守卫未登录跳转、刷新失败保留旧值、轮询启停、深浅色与中英文切换作为手工验收项。验收以监控页一次加载无报错、各卡片字段与后端概览一致、慢查询可打开画像、控制台可见分阶段耗时为准。
