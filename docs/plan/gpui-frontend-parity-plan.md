# GPUI 与前端功能对等计划

> 交付状态：六个阶段已全部实现并核验（桌面端检查通过，单测 7 通过）。

> 基线：前端 `frontend/src`（11 路由 + Schema 内 7 页签），GPUI `crates/linkrs-gpui`（16 Dock 面板）。
> 前序工作见《剩余工作细化方案》（阶段 A–G 已交付）。
> 本计划只收敛前端已具备、GPUI 缺失的能力；不新增后端接口，不引入新依赖。

## 1. 对照结论

GPUI 的服务接入层已与前端对等，差距集中在四处：写操作界面（Schema 数据浏览器行写）、
Console 编辑器深度、Monitoring 运维细节、全局横切（角色门控、空间联动）。向量、全文、
函数、配置四个面板 GPUI 反而领先（前端将其内嵌于其它页面），本计划只给它们补空间联动。

## 2. 分阶段任务

- 阶段一：角色门控与密码管理。登录后拉取身份并存入全局状态；管理类面板按角色隐藏；
  用户面板增加修改自己密码入口。
- 阶段二：Schema 写操作。建删空间、建删标签与边类型、增删属性的 ALTER、版本历史查看。
- 阶段三：数据浏览器行写操作与统计。选中行编辑（含乐观冲突保护）、删除、空间统计条。
- 阶段四：空间联动。向量与全文面板自动带入当前空间并提供一键填充；状态栏空间跳转到
  Schema 面板。
- 阶段五：Console 查询参数与会话变量。客户端新增带选项的执行方法，控制台提供两个
  JSON 输入并在执行时透传。
- 阶段六：监控慢查询与画像、批量任务文件载入。监控页增加慢查询表与画像查看；
  批量页支持用系统文件对话框载入条目。

## 3. 修改方案

### 阶段一：角色门控与密码管理

- 全局状态新增角色列表字段与配套读写方法：设置角色、清空角色（随登出）、
  管理员判定。管理员判定规则与前端一致：最高角色为 GOD、ADMIN、DBA 之一即具备管理权限，
  其余（USER、GUEST、未知）不可见管理入口。
- 登录流程在连接成功后追加一次身份查询，把返回的角色列表写入全局状态；失败不阻断登录，
  仅按无管理权限处理。登出时清空角色，与清空用户与空间保持一致。
- 主框架侧栏按管理员判定决定是否渲染管理组中的用户与会话入口；页脚展示当前最高角色。
- 用户服务新增修改自己密码方法，走查询语句通道（与前端同策略），转义规则与现有语句
  构造保持一致。用户面板增加独立的修改密码区（旧密码、新密码、二次确认），成功后清空输入。

### 阶段二：Schema 写操作

- 模式服务新增四个封装：删除标签、删除边类型、修改标签属性、修改边类型属性。
  其中修改走 ALTER 查询语句通道，增删属性片段的拼装规则与前端一致。
- 模式面板持有标签与边类型的完整信息（当前仅持有树节点，需额外保存），用于定位待改对象。
- 界面分三块：空间区（新建表单：名称、VID 类型；删除二次确认）、标签与边类型区
  （新建表单：名称 + 属性 JSON；删除二次确认；修改入口：新增属性行 + 勾选删除既有属性）、
  版本区（空间、名称、边标记、起止版本输入，历史、变更、破坏性检查三个查看动作，结果为 JSON 块）。
- 所有写操作成功后刷新树；失败走会话失效判定，与现有读路径一致。ALTER 无独立服务端点，
  走查询语句通道。

### 阶段三：数据浏览器行写操作与统计

- 客户端新增空间统计方法（对应空间统计端点），数据浏览器服务配套封装。
- 数据浏览器服务新增行写封装：顶点更新、顶点删除、边更新、边删除。语句构造规则
  （字面量转义、VID 引用、边的四元组定位、删除顶点自动带边）与前端模板一致。
  另新增按 ID 重读记录的方法，用于编辑前的冲突比对。
- 面板详情区下方增加编辑与删除动作：编辑打开 JSON 文本编辑器（复用多行编辑器组件），
  保存前重读比对，不一致则提示冲突并提供覆盖确认；删除走二次确认。
- 工具栏下方增加统计条：总顶点数、总边数、标签与边类型数量，读取失败不阻断主列表。
- 顶点与边的重读分别走现有管理器方法与客户端直调；边重读所需空间取自当前全局空间。

### 阶段四：空间联动

- 向量与全面板将其空间输入框的初始值与全局空间绑定：全局空间变化时若输入框为空则自动填入；
  另在输入行旁提供一键填充按钮。复用现有状态观察机制。
- 状态栏空间标签增加点击跳转到 Schema 面板（空间切换的唯一权威入口仍在 Schema 面板，
  本阶段不新增切换器）。

### 阶段五：Console 查询参数与会话变量

- 客户端在现有执行方法旁新增带选项的执行方法，请求体在原有字段基础上附带参数与会话变量；
  会话管理器与查询服务分别增加透传封装。原有无选项方法保持不变。
- 控制台新增可折叠的参数区：两个 JSON 文本输入（参数、会话变量），空输入视为未设置，
  非法 JSON 在执行前报错并阻断。执行成功与否的记录口径不变。

### 阶段六：监控慢查询与画像、批量任务文件载入

- 监控视图复用已有查询统计载荷，新增慢查询表（trace、会话、语句摘要、耗时、状态），
  行选中后调用画像接口拉取详情并渲染 JSON 块；失败仅影响画像区。
- 监控页新增阈值输入（CPU、内存、慢查询毫秒），超限时统计卡给出警示样式；阈值放面板本地状态，
  不持久化。
- 批量面板新增文件载入按钮，走系统文件选择对话框读取条目文件，解析复用现有条目解析逻辑。

## 4. 验证

- 每两个阶段合并做一次桌面端检查与单测，输出重定向到文件后读尾部确认。
- 手动验证清单：管理员与普通用户登录后的侧栏差异；空间建删与标签增删改；数据行编辑冲突提示；
  空间切换后向量面板自动填充；带参数查询执行；慢查询画像展示；批量文件载入。

## 5. 风险

- ALTER 与改密走查询语句通道，依赖服务端语句兼容；失败时错误透出，不做语义兜底。
- 空间统计端点随空间不存在而失败时，统计条静默隐藏，不阻断列表。
- 参数透传仅覆盖普通执行路径；流式与游标路径的请求体由服务端另一组端点承载，
  本阶段不改动。
