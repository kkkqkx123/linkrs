# 扫描枚举脚手架与外部身份解析：下一阶段设计

目标：把 group_by_count 剩余约 2ms 墙钟缺口中属于扫描侧的部分拿下（当前扫描工作量约 40ms：枚举约 23ms、可见性约 16ms；墙钟约 22ms，门为 20ms）。本方案只动扫描侧，不碰拓扑读取与聚合。

## 1. 成本结构（已核实）

分区 topology_only 列式扫描（group_by 锚点路径）的单行成本链：

- 存活枚举：`live_ids_in_range` 按 shard 区间逐行查时间戳数组 + 可见性判定（R2 后约 15ns/行）。已验证 provenance，下游不再复核。
- 外部身份解析：`IdManager::get_keys` 已是数组下标 + 整批单锁；逐行剩余为 `Option<IdKey>` 拷贝 + `vertex_id_of` 转换。`VertexId` 为内联定长数组（无分配），`IdKey::Int` 为纯拷贝，合计约 20–25ns/行。这是可见性计数的最主要成分，且为必需输出，不可跳过，只能压单价。
- 分片归并：R1 已把全局重排改为 k 路归并，约 0.5ms/分区。
- 脚手架余量：枚举计数中约三分之一暂无单独归属——按表加载的向量链（pending/merged/run）、按批的六个工作向量、`tags.names` 按批克隆、gate 与快照按批重建。单项皆小，合计约 5–10ms 工作量，是本轮最大的一块。

## 2. 实施顺序（先测量，后动手）

### E1：枚举子阶段计数（先行，无行为变化）

把 `scan_enumerate_us` 拆成表加载、窗口过滤、归并三段独立计数。目的只有一个：验证 §1 的脚手架占比估计，E2/E3 的取舍以此为准。若表加载占比不足一半，E2 降级为卫生项。

### E2：cursor 批间 scratch 复用

cursor 持有可复用工作向量（internal_ids、vids、run、merge runs），批间 clear 复用，不再按批重建。前置：cursor 为单分区线程独占使用（分区扫描每个分区独立 cursor，不跨线程共享），复用只发生在同一 cursor 的顺序 `next_column_batch` 调用之间。护栏：复用缓冲不改变任何输出内容与顺序；`clear` 后容量保留，长度语义与新建一致。验证：分配量下降 + 墙钟下降 + 全套件绿。

期望：拿下脚手架的主要部分，工作量约 -5ms（墙钟约 -0.5–1ms）。

### E3：外部身份解析融合转换

`get_keys` 回 `IdKey` 再逐行 `vertex_id_of` 转 `VertexId`，两步并一步：按表键类型一次分派，Int 表直接由内部 id 构造外部 id，跳过中间枚举与二次匹配；Text 表保持原路径。前置：按表加载时判定一次键类型，不逐行判定。护栏：Text 路径零改动；Int 构造与现有转换逐值一致（单测锁定等价）。验证：可见性工作量下降 + 全套件绿。

期望：约 -1–2ms 工作量（墙钟约 -0.2ms）。单价优化，到此外部身份解析视为收敛，不再继续压。

### E4：范围 walk 空洞（仅调查，不预设结论）

若 E1 显示空洞行过滤占显著比例，再考虑用空洞统计跳区间；否则不做。删除回收机制（lazy recycling）使 id 可能复用，任何跳跃必须以“不遗漏存活行”为前置证明，否则直接放弃。

## 3. 明确不做与诚实边界

- 不引入删除证明 token：版本链判定经 R2 后仅剩约两次比较，原方向一设计的收益上限（约 0.4ms 墙钟）不足以覆盖新标记的语义面，已评估放弃。
- 不改变扫描输出顺序契约：归并与复用都保持全局 id 有序，其它消费者（有序存在性、归并连接）不受影响。
- 不碰属性解码（已为零）、不碰拓扑读取（存储深水区，另立项）。
- E2+E3 合计期望墙钟约 -1ms；group_by 关门（20ms）可能仍需 E1 发现的新项或拓扑侧配合，本方案不承诺一次关门，承诺每项可验证、可回滚。

## 4. 门槛与验证

沿用既有门：结果逐值一致（group_by 为 [14|59] 等）、`result_stable=true`、`spill_rows=0`；生产默认口径（node1 绑定、三方 16 线程、warmup 1 + run 5 去最大值平均）；安静窗口复核墙钟，工作量计数器（各子阶段 us）作为结构性证据先行。

## 5. 实施结果

E1 已落地：`ScanTimings` 保留 `scan_enumerate_us` 总量，并新增表加载、窗口过滤、分片归并三个互斥分量，穿透 `ColumnarStats`、EXPLAIN 与基准 JSON。生产默认 `group_by_count` 两轮计数器分别为枚举 25057/29387us，其中表加载 18489/21237us（约 74%/72%）、归并 6568/8147us、窗口过滤 0us；可见性 15176/17533us。表加载确为枚举主体，支持 E2 方向；窗口过滤为零，E4 空洞跳跃不做。

E2 已落地：游标持有跨批复用的工作向量，范围过滤、候选、run、选择向量和分片 run 槽位均 clear 后复用；表加载时按目标向量填充，不再按批重建这些中间容器，已解析身份直接借用游标窗口而不再按批复制。全局有序归并契约不变，分片 run 槽位在下一张表复用时保留嵌套容量。微基准拓扑切片分配量由上一轮 290 B/row 降至 270 B/row（原始基线 334 B/row），全表拓扑由 286 B/row 降至 253 B/row。

E3 已落地：空格的 `vid_type` 在游标打开时解析一次键形态；整数表走直接整数键批量读取并构造 `VertexId`，文本表保留原 `IdKey` 路径。整数与文本两条路径均有用例逐值锁定转换等价与有序输出。

devs 编译通过（release bench 二进制 `BUILD_EXIT=0`）。正确性门全绿：storage lib 1422/1422、column_batch 13/13、query stats 91/91、api lib 30/30，配置默认、partitioning 50/50、typed group 9/9、local topk 13/13、parallel 27/27、DQL 324/324。两轮生产默认结果保持 `group_by_count [14|59]`、`distinct_limit [14]`、`join_two_hop [382018]`、`variable_path_count [400153]`，`result_stable=true`、`spill_rows=0`。

墙钟未关门：生产默认 `group_by_count` 三轮为 31.87/32.70/32.22ms。复测期间 devs 负载均值 35–52、分区偏斜 1.70/1.12/1.47，不属于设计的安静窗口；最后一轮工作量计数器为枚举 26921us（表加载 19064us、归并 7857us、窗口过滤 0us）、可见性 15557us，与基线同一量级，未见结构性回归。墙钟结论需在安静窗口复测，本轮不宣称 -1ms 收益或 20ms 关门。
