# 两跳计数读取合并设计

**日期**：2026-11-19  
**问题来源**：`docs/issue/linkrs-remaining-parity-issues.md` 第 19 节方案阶段二回填。本文件只描述剩余改进的设计、护栏与验收，不重新定义问题。

## 现状与定位

devs 上 `EXPLAIN ANALYZE` 显示两个固定门用例的 `StorageScanVertices` 均约 0.5 ms，全部时间落在 `ExpandAll`：两跳约 15.3 ms，变长 `1..2` 约 15.5 ms。当前执行路径在每一层做两次独立批量调用：先取邻接顶点外部 ID，再按这些 ID 读尾边度数。中间结果包含外部 ID 翻译、每个种子的去重集合和一批临时向量；对于闭合单标签、单方向、单类型的窄形状，这些工作都不参与最终计数。

## 目标

在不改计数语义、不放宽快路径前置、不启用分区的前提下，把两跳与 `1..2` 变长计数的展开成本再压低一档。九条纯计数、`group_by_count`、`distinct_limit` 必须保持原计划和原数值。

## 修改位置

- 存储查询 trait：新增按批返回「每个源点的邻居度数之和」的只读原语；默认实现复用现有两次调用，保证适配器行为不变。
- 原生存储引擎 reader：为单类型、单方向形状提供内部实现；其余形状直接回退默认语义。
- 查询层计数尾：固定深度 `2` 与范围 `1..2` 直接消费新原语；TTL、开放 schema、受限路径语义继续走物化行数回退。
- 遍历相关测试：补内部实现与默认实现的等价比对，保留自环、重复边、空端点、TTL 反例。

## 做法

存储原语的入参与现有批量邻接接口一致，返回每个源点一条计数。原生实现先按边类型解析 schema 并读取一次邻接，把远端点保留为内部行号；随后在另一个读锁窗口内按这些行号读取同类型、同方向的尾边度数并累加。锁顺序仍为「先边表、释放后再读另一张边表」，避免在回调中嵌套取锁。邻接按边出现次数累计，不按目的顶点去重，因此自环和平行边的 walk 计数不变。

内部实现只覆盖解析后恰好一个边类型且方向为 `Out` 或 `In` 的形状。`Both`、多类型、无法解析 schema 的形状交给默认实现：先取外部邻居 ID，再按外部 ID 读出度求和。第一遍暂存的内部端点按快照批量解析一次外部 ID，以复用原路径对悬空邻居的丢弃语义；解析结果不进入查询层行，仅在存在变更记录器时额外记录读集合。

查询层对固定深度 `2` 只调用一次新原语；对范围 `1..2` 再叠加一次源点出度求和。原先把前沿展开成顶点 ID 向量的循环仅保留给其他深度范围；当前优化器只放行 `2` 与 `1..2`，因此这两条路径是唯一的生产快路径。

## 护栏

- 只在 `closed_loop`、无 TTL、无属性需求、无路径约束、无空路径注入时启用；任一不满足立即回退。
- 计数单位仍是边出现次数，不按顶点去重；自环与平行边由测试锁定。
- 不改变拓扑/属性布局、边身份、MVCC 权威和同步点；不建立跨调用可见性缓存，不把属性内联进 CSR。
- 新接口默认实现保证非原生存储适配器的数值不变；显示分支不参与计划决策。

## 验证与回滚

devs 上完成 release 编译；运行 `expand_pushdown` 单测、DQL、streaming lib 与 `parallel_partition_execution`。固定门沿用 LSQB sf0.1、`--parallel-workers 16`、绑核 `16-31`、warmup 1 + run 5，至少四轮，与本轮 13–14 ms 基线对比，同时记录九条纯计数和另外两个固定门用例。若数值不一致或耗时无收益，回退存储 trait、原生 reader 与计数尾三个原模块即可，不需要数据迁移。
