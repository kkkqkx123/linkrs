# CSR 按 Ladybug 模式重构分阶段方案

依据：`docs/analysis/csr-design-analysis.md`（现状与问题定位）、
`docs/analysis/csr-comparison-and-design.md`（全面对比与目标设计）。
本文只排实施顺序与每阶段的验收线，不重复设计论证。

## 1. 总原则

1. **判定唯一按对比结论**：十六个设计维度 Ladybug 占优，目标即第 5 节的目标设计，不因迁移成本打折。
2. **不做任何向后兼容**：旧整体转储格式直接拒绝报错，不设识别与转换分支；删形态即删其序列化分支。
3. **不建替代性新模块**：所有改动在原 `edge` 模块内按职责拆分，不出现“第二套”实现。
4. **正确性先行**：先修结构债（双重索引、三副本可见性），再动性能路径（扫描、压缩、落盘）。
5. **验证合并**：每阶段末集中编译与测试一次，阶段内不反复全量编译。

## 2. 阶段划分总览

| 阶段 | 目标 | 主要触及范围 |
|---|---|---|
| 阶段一 | 统一行空间与可见性单真相，收敛变体 | `edge_table/core、mvcc、persistence`，`csr_with_properties`，`csr_variant` 及被删形态 |
| 阶段二 | 读路径流式化与列裁剪 | `edge_table/iterator、core` 的扫描与物化接口 |
| 阶段三 | 写路径 Ladybug 化（暂存层、增量回收） | `edge_table` 写链路，`mutable_csr` 溢出与压缩，`fragmentation_stats`，与 `graphdb-transaction` 对接 |
| 阶段四 | 分片与增量检查点 | 节点组集合、区域检查点、重映射、预写日志回放 |
| 阶段五 | 编码接入列路径与观测收敛 | `encoding` 接入列路径，列统计，布隆去留，模式变更状态机 |

后一阶段以前一阶段验收通过为前置条件，不并行。

## 3. 阶段一：统一行空间与可见性单真相

### 3.1 目标

同一条边的邻接寻址只存一份，边生死只由一处判定。消除双重索引与三副本漂移。

### 3.2 改动

1. 属性表并入统一行空间：删除 `CsrWithProperties` 自带的起止与头指针数组，
   属性列以下拓扑行号为唯一下标，寻址只算一次。
2. 可见性以版本链（`MVCCManager` 演进形态）为唯一真相：
   邻接与属性行的物理时间戳不再参与判定，只保留回收所需的最小投影，
   最终随版本链完整落地后移除；墓碑表合并入版本记录，不再独立维护。
3. 收敛变体：删除按标签分组与定长多槽两种形态及其序列化分支，
   只保留通用多边与单边；修复单边形态持久化丢失创建时间的缺陷。
4. 持久化收紧：拓扑与属性行数校验统一为显式错误，消除落盘前整表克隆，
   旧格式一律拒绝。

### 3.3 验收

- 一致性测试：拓扑行数恒等于属性行数，插入、删除、回收、重映射后依然成立。
- 时间旅行测试：各保留形态下历史快照读一致，单边形态不再失真。
- 现有 `compaction.rs`、`persistence_recovery.rs`、`transaction_isolation.rs` 通过。
- 拒绝测试：旧格式文件加载必须显式报错。

## 4. 阶段二：读路径流式化与列裁剪

### 4.1 目标

扫描不再全表物化，遍历默认只读拓扑，属性按需延迟物化。

### 4.2 改动

1. 全表与邻接扫描迭代器改为流式推进，构造时不再物化记录向量，
   限流在推进侧生效。
2. 扫描接口接受列子集声明，遍历查询默认只取邻居列，
   属性在命中后再按边标识取列快照。
3. 点查、邻接、过滤扫描共用同一套行定位逻辑，不保留独立物化类型。

### 4.3 验收

- `edge_range_scan_test.rs`、`edge_predicate_scan_test.rs` 通过并补列裁剪断言。
- 遍历基准（`traversal_perf_bench`、`neighbor_batch_bench`）对比阶段前有可观测改进，
  大邻接表扫描内存峰值下降。
- `full_lifecycle.rs`、`scenario.rs` 通过。

## 5. 阶段三：写路径 Ladybug 化

### 5.1 目标

写入不再原地修改服务中的结构，不再手写多步补偿；回收不再全表重建。

### 5.2 改动

1. 引入本事务暂存表：未提交写只进暂存，与已提交数据物理隔离；
   提交时按行索引批量搬入内存追加层并打提交时间戳，失败只丢弃本次搬入。
   回滚语义与 `graphdb-transaction` 对接，删除现有逐项逆操作补偿链。
2. 行级空隙与按顶点增量回收：日常写入先填空隙，空隙耗尽只重平衡所在顶点，
   不再整表重建；统一预留比例改为按行空隙维持。
3. 修复碎片统计遗留字段，使其真实反映主区与溢出块的浪费，
   触发器按顶点粒度判定。

### 5.3 验收

- `concurrent_operations.rs`、`transaction_isolation.rs`、`fault_recovery.rs` 通过，
  重点覆盖提交失败无半写、回滚无残留。
- 回收测试：高度数顶点写入后回收停顿有界，不再出现整表重建。
- 写入与回滚基准（`write_gate_bench`、`rollback_bench`）对比阶段前改进。

## 6. 阶段四：分片与增量检查点

### 6.1 目标

数据按端点区间分片，落盘按脏区增量进行，单点写入只影响所在分片；
恢复具备重做能力。

### 6.2 改动

1. 按端点区间切分节点组，每组独立持有落盘块、内存追加层与行索引，
   头部寻址双列随组持久化。
2. 落盘数据区按叶区分层，密度要求自底向顶渐变；
   区域记录插入、持久删除、各列更新三类脏标记，全无则跳过；
   脏叶区按密度界逐级合并，小写入不引发大搬迁。
3. 顶点压实按组逐个重建头部与行空间，跨组引用随组搬迁逐组翻译。
4. 预写日志覆盖已提交未落盘操作，恢复流程为加载检查点后回放，
   回放幂等。

### 6.3 验收

- 大规模导入基准（`import_bench`、`indexed_bulk_load_bench`）随规模线性可扩展，
  检查点停顿有界。
- `wal_recovery.rs`、`persistence_recovery.rs`、`generation_rebuild_crash.rs`、
  `split_crash_safe.rs`、`barrier_fence.rs` 通过，覆盖断电与崩溃恢复。
- 全表碎片率只做观测，不再作为回收触发器。

## 7. 阶段五：编码接入列路径与观测收敛

### 7.1 目标

现有编码算法库真正生效，统计与辅助结构无半成品。

### 7.2 改动

1. 定长列、浮点列、字符串列、常量列分别接入位打包游程、自适应编码、
   字典前缀压缩、单值存储，头部列同样走列路径。
2. 列统计随刷盘生成并持久化，检查点收集版本快照供优化器使用；
   碎片、密度、落盘量纳入统一指标注册。
3. 删除布隆要么接入删除定位路径并度量命中率，要么删除。
4. 加列改为显式状态机：准备、填充默认值、随检查点落盘、发布，每步可回滚。

### 7.3 验收

- 列存批量与裁剪测试（`column_batch_test.rs`、`zone_map_prune_test.rs`）通过。
- 存储基准（`storage_bench`、`storage_read_baseline`、`edge_scan_speedup_bench`、
  `olap_e2e_bench`、`columnar_necessity_bench`）全面对比阶段前。
- 无恒零统计字段，无未接入主路径的装饰结构。

## 8. 风险与取舍记录

1. 阶段一删除两种形态与旧格式是破坏性变更，按无兼容原则直接执行，
   调用方（查询引擎与上层 API）需同步清理分支。
2. 阶段三与事务层对接是最大语义变更点，需先冻结可见性语义（创建时间晚于查询不可见，
   删除不晚于查询不可见，同戳删幂等，异戳冲突报错），再改写路径。
3. 阶段四之前不承诺大表性能数字，阶段四之后以实测为准重估密度与分片参数。
