# DDL 遗留项长期补充方案

## 1. 背景与范围

`ddl_leftover_items.md` 与 `ddl_leftover_deferred_evaluation.md` 均已实施完成：再评估文档中的两个立项
（维护语句权限分类修正、TTL 后台自动清理）已落地，发布文档《03_ddl_schema_definition.md》的
TTL 与 PURGE 章节、《07_configuration_reference.md》的存储配置项均已同步。

本文只处理再评估结论中**未实施、但长期仍可能需要补充**的剩余项，逐项给出"是否需要补充、何时触发、
以什么最小形态落地"的判断与设计方案。已永久维持不做的项在第 7 章汇总，不在本文展开。

判据沿用再评估文档的三条：契约悬空、防误用、保持单机轻量。长期项不等于永远不做——每项均给出

## 2. 补充一的前置事实：权限分类不只是"长期统一项"

再评估文档把"语句类别 → 权限映射"记录为暂不立项的后续统一项，理由是前缀枚举每新增一个维护语句
都要补一处。以最小改动补上 `PURGE` / `CHECKPOINT` 两个分支之后，粗粒度通道的前缀枚举问题
依然存在，且它当前承载着一个可达的越权路径：

- `extract_permission_from_statement`（`crates/linkrs-server/src/graph_service/guard.rs`）仍按
  首关键词前缀映射，未命中分支一律按只读放行。
- 用户管理门禁的预过滤（同文件 `check_user_management_permission`）仍是九个字面前缀。词法器把
  `CREATEUSER` / `ALTERUSER` / `DROPUSER` / `CHANGEPASSWORD` 识别为单 token
  （`crates/linkrs-query/src/parser/lexing/lexer/token.rs`），并由 dispatch 直接路由到 UserParser
  （`crates/linkrs-query/src/parser/parsing/stmt_parser/dispatch.rs`）。这些粘连词形与
  `CREATE  USER`（双空格，解析层的空白用例即覆盖该形态）都漏过预过滤，落入粗映射：
  建用户/删用户按 Write 放行、改他人密码按只读放行。
- 执行后的状态对齐（`crates/linkrs-server/src/graph_service/query.rs` 的
  `is_user_management_statement`）使用同一套前缀，对这些变体同样失效，会话驱逐与角色同步被旁路。

即：`docs/issue/dcl-auth-bypass-prefix-matching.md`（P0）与 `docs/issue/dcl-permission-matrix-drift.md`
描述的绕过路径在代码中仍然成立，`docs/plan/dcl_user_management_fix.md` 的阶段零（授权分类改为按
语句变体判定）未实施。因此这一项的性质不是"枚举维护成本"，而是**正确性修复**：再评估文档的立项一
只补了两个分支，病根未除，下一个新增维护语句会再次落到只读默认分支上。

## 3. 补充一：权限分类改为按解析后语句类别推导

目标态：查询通道的权限判定只有一处实现，输入是解析后的语句；解析失败显式失败，不回退到宽松默认；
语句类别到权限的映射集中在一处并注明来源；用户管理语句的准入与执行后对齐共用同一判定。

设计要点：

- **单一判定入口**。把粗粒度前缀映射与用户管理专用分支合并为一个函数，输入为 `&Stmt`（解析能力
  已具备，`parse_stmt` 已在同文件使用）。调用方先解析，解析失败返回可读错误，不再有"按只读放行"
  的兜底分支。无法或不需解析的路径（事务命令、会话语句）单独枚举，与"解析失败"分开表达。
- **映射输入选型**：语句类别做粗分，语句变体做细分。查询与事务、会话语句按类别即可定权；DML 写
  语句（INSERT/UPDATE/UPSERT/MERGE/DELETE）与 schema 语句（CREATE/DROP/ALTER 各类目标）需要按
  变体区分——`CREATE TAG` 与 `CREATE INDEX` 同首关键词但权限需求不同，这正是前缀方案的失效点；
  维护语句（`PURGE EXPIRED`、`CHECKPOINT` 等）按变体显式列举，落入 schema/维护级或写级别。
  类别到权限的默认映射写成显式表，不写 `else` 兜底：新增语句若未在表中出现，编译期或测试期即暴露，
  而不是运行时静默放行。
- **执行后对齐共用同一判定**。`is_user_management_statement` 改为调用同一函数，消除字面前缀旁路，
  使会话驱逐与角色同步对准解析结果。
- **权限种类不扩**。不新增 `Permission` 种类、不新增角色等级；仅修正既有五种权限的归属。GOD_SPACE_ID
  回退与 `is_admin` 跨空间放行属既定模型，在文档写明即可，不在本项改语义。
- **与管理通道的关系**。HTTP 管理通道的 `OperationType` 体系按"操作"而非"语句"建模，职责不同，
  不以代码合并为目标；以集成测试保证"同一操作在两条通道判定一致"。
- **测试**。九个 DCL 变体 × 相关角色 × 一元与流式入口的拒绝/放行矩阵；粘连词形、双空格、tab、
  前导空白等形态必须与规范拼写行为完全一致；解析失败语句不得被任何角色放行；God/Admin/DBA 对
  各语句的正向用例作为回归保护。
- **风险与回退**。判定收紧可能挡掉既有合法用法：以正向矩阵兜底，回退即还原单一判定函数。错误信息
  保持 `Permission check failed: ...` 可读形态，不把拒绝原因吞掉。
- **文档**。《04_dcl_user_management.md》文末权限矩阵逐行对齐代码；在矩阵旁写明判定依据是解析后的
  语句类别，不是语句文本。

## 4. 补充二：tag/edge 注释修改能力

背景：上游 `ALTER TAG` / `ALTER EDGE` 支持 `COMMENT = '...'` 变更项（对照见再评估文档证据索引）；
linkrs 当前仅创建期可设注释。`TagInfo` / `EdgeTypeInfo` / `PropertyDef` 都已带 `comment` 字段，
属性级注释在 `ALTER ... ADD` 路径已可用——缺的是 schema 级注释的修改入口。

触发条件（再评估文档记录，任一成立即立项）：`SHOW CREATE` 需要完整回显注释；用户侧出现成规模的
注释维护诉求。两者相互独立：回显缺口是观测问题，修改入口是能力问题，不会互相阻塞实施。

目标态：`ALTER TAG <name> COMMENT = '<text>'` 与 `ALTER EDGE <name> COMMENT = '<text>'` 可改，
`DESC` / `SHOW CREATE` 回显新值，重启后持久化；与属性注释的修改能力对等；未引入新的 WAL 操作码。

设计要点：

- **语法与 AST**。ALTER 变更项列表新增注释项，沿用赋值形态；`AlterTarget::Tag` / `Edge`
  （`crates/linkrs-query/src/parser/ast/stmt/ddl.rs`）各增加注释字段。解析层给出可读错误：
  非法字面量、同一语句重复指定注释。
- **校验口径对齐创建期**。长度上限、字符集与 `CREATE` 侧一致，避免两条路径口径漂移；空注释语义
  二选一并写入文档（清空注释，或显式报错），不允许静默忽略。
- **存储层**。`alter_tag` / `alter_edge_type`（`crates/linkrs-storage/src/client/traits_schema.rs`）
  当前入参只有属性增删；扩展为携带"只改注释"的更新，走既有 schema 更新与 redo 通道。**不新增
  WAL 操作码**：与"不为 PURGE 新增操作码"同一判据——复用既有记录，避免改恢复链路而无收益。
- **回放与格式**。redo 回放分支随之支持注释字段；WAL 版本号的处置沿用既有原则：schema 元数据序列化
  格式若变化则提升版本号，旧文件显式拒绝启动，不做部分回放。
- **读路径**。`DESC` / `SHOW CREATE` 读取注释的链路已存在（读创建期值），只需保证更新后可见；导出与
  迁移的 schema 快照若含注释则自然跟随，无需专门改动。
- **测试**。解析合法与非法形态；执行后 `DESC` / `SHOW CREATE` 回显；重启后经 redo 回放注释持久；
  与 `ADD` / `DROP` / `CHANGE` 组合使用的语句形态；注释长度超限报错。
- **文档**。ALTER TAG / ALTER EDGE 章节补语法与语义；把"仅创建时可设"的边界声明改写为"可经
  ALTER 修改"；同步 `SHOW CREATE` 输出说明。

## 5. 补充三：计数路径 TTL 口径分层

现状：`count_vertices_by_tag` 定位为洞统计近似值，`count_edges_by_type` 定位为可见性门行计数，
二者都不物化属性、不判定 TTL；发布文档已声明统计数值可能包含过期行。TTL 后台清理上线后，过期行
被物理删除，两个口径自然收敛——这是零代码成本的收敛路径。

分两档，按需取一，不默认做档位 B：

- **档位 A（默认，零代码）**。文档口径明确为"计数含尚未物理清除的过期行；开启后台清理或执行
  `PURGE EXPIRED` 后收敛"，与上游一致。优化器统计收集器维持近似口径。
- **档位 B（触发条件：精确基数成为计划质量瓶颈）**。新增**独立的精确计数入口**，不改造现有两个
  入口——它们的定位分别是近似估计与廉价行计数，改造等于放弃定位。实现要点：按 schema 遍历可见行，
  只解码 `ttl_col` 单列（不全量物化属性），按既有 TTL 判定谓词过滤后计数；计数结果按 schema 版本
  与数据版本缓存，TTL 配置变更即失效；仅在调用方显式请求时走精确路径，统计收集器默认不变。
  精确值与近似值的差值还可作为后台清理效果的交叉验证指标。

## 6. 补充四：TTL 后台清理的契约与观测收尾

两个立项的落地留下一处文档与实现不符，需收口：

- **并发口径修正**。发布文档当前写"显式语句与后台清理由该单实例天然串行化"。实现上 purge 无互斥，
  显式语句在请求线程执行，与后台任务可并发。删除走 MVCC 写路径且幂等，并发安全，但文档表述与实现
  不符。改为"二者共用同一 purge 实现，删除幂等、可并发执行，无互斥锁，安全性由 MVCC 与幂等保证"。
- **失败语义写明**。单轮内某空间失败已按 warn 跳过、不影响其余空间；文档补一句"失败空间下一轮重试"，
  避免运维误判为清理未启用。
- **观测**。指标 `linkrs_ttl_purge_cycles_total` / `linkrs_ttl_purge_rows_total` 已足够支撑
  "是否在转"的判断；如需"最近一轮时间、各空间失败原因"，追加日志字段即可，不新增管理端点与 proto，
  保持单机轻量。

## 7. 长期维持不做项与复审条件

- `ALTER SPACE ... SET COMMENT`：与上游一致（该版本 `ALTER SPACE` 无注释子句）。复审条件：上游新增
  该子句。
- PURGE 专用 gRPC / HTTP RPC：通用查询通道已覆盖全部入口，与上游"维护复用语句通道"同构。复审条件：
  出现 CLI 与嵌入式均无法满足的运维场景。
- 为 PURGE 新增 WAL 操作码、重编号 WAL 判别式：纯内部格式决策，无外部消费方，改动只增恢复链风险。
  复审条件：无。
- 计数路径档位 B：触发条件见第 5 章。

## 8. 实施顺序、依赖与验收

| 顺序 | 项 | 规模 | 依赖 | 验收 |
|---|---|---|---|---|
| 1 | 补充一：权限分类按语句类别推导 | 中 | 无 | 拒绝/放行矩阵全绿（含形态变体与解析失败）；一元与流式一致；权限矩阵与代码逐行对应；`cargo check --workspace` 零告警 |
| 2 | 补充四：TTL 清理契约与观测收尾 | 小 | 无 | 文档表述与实现逐条对应；指标与日志字段由既有测试覆盖 |
| 3 | 补充二：tag/edge 注释修改 | 中 | 无强依赖 | 解析、执行、回放、回显四类测试全绿；WAL 相关测试不回退；文档与实现逐条对应 |
| 4 | 补充三：计数口径分层 | 小 | 档位 B 依赖 TTL 判定谓词复用 | 档位 A 仅文档；档位 B 需精确/近似差异断言 |

补充一先行：它是正确性修复且是其余权限相关改动的地基。补充三的档位 B 与补充二无耦合，可单独推进。
验证方式合并为少量构建：`cargo check --workspace` 一次；`cargo test -p linkrs-query -p linkrs-server`
与 `cargo test -p linkrs-storage -p linkrs-core` 各一次。
