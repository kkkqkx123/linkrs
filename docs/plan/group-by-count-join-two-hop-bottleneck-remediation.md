# `group_by_count` 与 `join_two_hop` 瓶颈分析及收敛方案

**日期**：2026-11-26
**定位**：本文件针对问题清单中的 `group_by_count` 与 `join_two_hop` 缺口给出瓶颈归因与修改顺序，不重新定义问题。完成定义与验收口径以 `docs/issue/linkrs-remaining-parity-issues.md` 为准。基线为 2026-11-25 资源对齐重测与有序存在性全量 gate，旧口径数字一律作废。

## 1. 当前基线

生产默认（8 workers / 8 partitions，有序并行展开放行，计数前沿不放行），devs 机 node1 绑定，warmup 1 + run 5 去最大值平均：

| 用例 | Linkrs 生产默认 | Ladybug | 倍率 | 完成门 |
|---|---:|---:|---|---|
| `group_by_count` | 26–33ms | 8.16ms | 约 3.2× | ≤20ms 且 ≤3× |
| `join_two_hop` | 约 5.4ms | 1.54ms | 约 3.5× | ≤3ms |

证据目录：`perf-data/parity/results/2026-11-25/resource-aligned/`、`perf-data/parity/results/2026-11-25/ordered-existence-remediation/prod-final/`。`distinct_limit` 已由有序存在性扫描闭环（约 1.8ms，反超 Ladybug），`variable_path_count` 大幅领先三方，均不在本文件范围内。

## 2. `group_by_count` 瓶颈

查询形状为单跳出边展开后按目的端主键分组计数再取 Top 10。聚合本身已出局：typed 分组全命中、零回退，Exchange 前局部 TopK 已把交换行数收敛到百行量级，展开输出物化为零。剩余成本全部在读取侧，生产默认 8 分区工作量之和（215488 父与边，30536 唯一目的端）分解如下：

- 扫描约 43ms：枚举约 24.5ms（约 114ns/行）、可见性复核约 15.8ms（约 73ns/行）；拓扑-only 扫描，属性解码为零。
- 展开约 77ms：拓扑区间读取约 65ms（约 300ns/边）、目的端存在性读取约 12ms（约 390ns/唯一目的端）、视图组装约 0.6ms。
- 编译约 2.4ms，占端到端约 9%；简单查询编译仅约 0.02ms。
- 分区间最大与最小耗时比约 1.6 倍，墙钟由尾部分区决定；工作量总和相对墙钟并行效率正常。

对照：单线程微基准每边约 126ns，而并行工作量均摊约 300ns，差值主要来自每父批的边表读锁获取与逐顶点读集合记账；目的端存在性读取的唯一目的是过滤悬空邻居。

## 3. `join_two_hop` 瓶颈

查询形状为固定两跳同类型同方向纯计数，结果恒为 382018。该形状当前串行执行，扫描约 0.5ms，二跳 count-only 前沿算子耗时约 8.1ms，占端到端九成以上，编译可忽略。成本构成为首跳批量邻接遍历产生中间前沿，随后对前沿做外部身份批量解析（只为悬空邻居可见性过滤）与按内部行号的尾边度数随机读取并求和。对手按邻接偏移直接累计、不解析邻居身份，这是倍率差的主要来源。另有观测缺口：该前沿路径的展开自耗时计数器未被覆盖，以 EXPLAIN 算子耗时为准。

## 4. 修改顺序

按期望收益从大到小依次实施，前一项未达预期先复盘再进入下一项。任一快路径必须先补反例与空输入用例；所有改动收敛到原模块。

其一，按度数感知切分分区工作。当前按行数均匀切分，度数偏斜使尾部分区决定墙钟。落点为分区规划的切分策略，用已有采样估计每分区边数，按边数而非行数均衡切分。护栏为只改变分区边界，不改变行归属与顺序语义。验证为分区耗时极差收敛、墙钟下降、结果逐值一致。

其二，存储侧维护无悬空边证明，成立时跳过存在性类读取。该证明同时服务两个用例：分组用例跳过每个唯一目的端的存在性读取，两跳用例跳过中间前沿的外部身份批量解析与逐邻居过滤，直接按内部端点读尾边度数求和。落点为存储侧边类型粒度的悬空边标记，顶点删除、悬空修复与导入路径均需更新标记；查询侧仅在标记成立且运行时标签与计划一致时跳过，否则保持原路径。护栏为无证明不断任何存在性读取。验证为标记开 / 关对照结果逐值一致，对应自耗时下降。

其三，放行并行计数前沿。两跳形状当前并行度为零，1700 个种子天然可分，分区内独立求首跳邻居与尾边度数、末端求和。落点为分区规划与前沿执行，保留同轮结果稳定性校验。护栏为默认可一键关闭，多类型、`Both` 方向、TTL 形状不放行。验证为冻结库同二进制开 / 关对照八轮以上逐值一致。

其四，收紧批量读取的锁与记账开销。整分区扫描期间复用同一读守卫，按批记账替代逐顶点记账，记账仅在记录器激活时执行。护栏为不改变读时间戳语义与并发写入可见性。验证为微基准与固定门工作量同时下降，数值不变。

其五，度数读取前按内部分片与行号重排中间端点，把打散在 CSR 头部的随机读变为顺序读；重排只发生在计数累加内部，不改变任何输出顺序。验证为微基准随机度读耗时下降，端到端数值不变。

其六，复用已编译计划，覆盖该并行形状；缓存命中不得绕过语义守卫的运行时复核。验证为二次执行编译耗时量级下降，结果一致。

## 5. 门槛与不做

门槛为 `group_by_count` 生产默认不超过 20ms 且与 Ladybug 倍率不超过 3 倍、`join_two_hop` 生产默认不超过 3ms 且结果恒为 382018；任一数值回归立即停止，先补反例再继续。门槛未达成不通过放宽并行、近似、截断或放宽 buffer 策略换取。

不做项：近似聚合与采样截断；跨调用可见性或端点存在性缓存；属性内联进 CSR；无证明的存在性跳过；多谓词组合下推；去重计数向量化。

## 6. 实施结果（2026-11-26，devs 实测）

口径为 node1 绑定、三方 16 线程、warmup 1 + run 5 去最大值平均；v4 库。正确性门全绿：query lib 2364、storage lib 1420、DQL 324、parallel 27、typed group、local topk、column batch 与新增单测（token 生命周期、degree sketch 切分）。

- 其一（度数感知切分）：已生效，固定门 EXPLAIN 显示 `degree-weighted`，分区偏斜比由约 1.6 降到约 1.1–1.3。形状为 stride 采样累计权重等分，退化时回退均匀切分。
- 其二（无悬空边证明）：已生效。prove 开 / 关对照结果逐值一致；`dangling_exist_skips` 为 group_by 112/112 批、join_two 与变长计数各 2/2 前沿调用；group_by 目的端读取工作量由约 11ms 降到 0。token 由插入校验、plain 删除撤销、修复重建三条规则维护，重启后懒播种标脏。
- 其三（并行计数前沿）：已生效。种子门槛（每 worker 32 种子）替代行数门后 join_two 进入并行（`actual>=2`，偏斜比约 1.1），串行约 5.4ms 降到约 3.7–3.9ms。`allow_parallel_count_frontier` 默认开启，保留一键关闭。
- 其四（记账收紧）：已闭环。批量方法下沉到事务 trait（`record_vertex_reads` 默认逐条，真记账实现单守卫批量插入，auto-commit 空记账实现空体跳过虚调用），存储侧扫描与属性批量路径的逐行记账全部改为批量；等价性单测断言批量与逐条产出同一 read set。batch_acct 对照：group_by 22.58→22.01ms（扫描工作量约 -0.3ms），join_two 3.75→3.10ms（锚点扫描批量记账叠加负载窗口，机制为真、幅度待安静复核），结果逐值一致。未动项：边扫描路径的逐条边记账（冷路径，无热点依据不动）。
- 其五（端点排序读度数）：已随前沿路径落地，只改变度数读取顺序，不改变累加结果；未单独 A/B，按语义中性保留。
- 其六（计划复用）：已闭环。compiled memo 全命中，group_by 编译由约 2.4ms 降到约 0.05ms，join_two 由约 0.02ms 降到约 0.03ms 量级（原本已低）。

生产默认对照（prove 开 / 关，v4 库）：group_by 22.58 / 23.52ms，distinct_limit（无序索引的旧路径）21.84 / 29.53ms，join_two 3.75 / 4.03ms，variable_path_count 5.47 / 5.68ms。相对资源对齐基线：group_by 26.41→22.58（对 Ladybug 2.77×），join_two 5.41→3.75（对 Ladybug 2.43×）。完成门（20ms、3ms）尚未同时达成：剩余主因是扫描可见性（约 16ms）与单跳拓扑读取（约 55ms），分区扫描与 CSR 区间读取是下一轮主线。

后继（见 followup 设计文档实施 §4）：其四闭环后 join_two 门已关闭——前沿分段计数显示尾边读主导，重复端点去重读数使 tail 工作量 3592→443µs，join_two 达 2.96ms（安静）/ 1.49ms（高负载，工作量结构性下降），variable_path 同路径 5.47→1.92ms；group_by 最优 22.01ms，门仍差约 2ms，待安静窗口复核与扫描深水区工作。
