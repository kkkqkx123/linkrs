# 元数据计数设计与实施

日期：2026-11-16
对应问题：`docs/issue/count-slow-vs-ladybug.md`
前置方案：`docs/plan/count-slow-vs-ladybug.md`（元数据计数章节）

## 目标

纯 `COUNT` 查询不再扫描任何行，直接从存储元数据取数：

- 顶点纯计数：`MATCH (n:T) RETURN count(n)` 从顶点表存活枚举取数，不跑游标。
- 边纯计数：`MATCH (:A)-[k:T]->(:B) RETURN count(k)` 从边表可见性游走取数，不扫源顶点、不组装行。

数值必须与现有执行路径逐行一致，任一门限不满足即走原路径。

## 为何放在执行器装配层

计划改写需要新的计划节点或注解字段，会牵连序列化、内存估算与解释输出；装配层已有按子树形状检测的先例（`count_only` 系列辅助函数），检测与折叠都收敛在一处。串行装配按自底向上递归，聚合节点是折叠整条纯计数链的天然拦截点；分区装配路径保持不动，天然退化为原慢速但正确的计划。

## 折叠形态

聚合节点同时满足全局计数形状与下方纯计数链时，装配不再递归构建子链，而是直接构建两段式折叠链：新的元数据源算子发射单行计数值，阻塞聚合把全部 `COUNT` 改写为对该列的求和（与既有 `count_only` 改写同一语义）。被跳过的中间投影只可能是被计数变量的裸透传，无子查询、无副作用，跳过不改变语义。折叠链之上的输出别名、排序、截断等节点保持原样。

数据源发射的列沿用既有计数列名，聚合输出列名沿用原聚合节点列名，解释输出把该源标记为元数据计数并如实报告单行基数。

## 顶点门限

链条为聚合经裸透传投影与扫描隐含的标签过滤（常量真残留或与扫描同标签的标签成员检查）直达顶点扫描，且扫描带确定标签（无标签视为全标签求和，需全部标签逐一满足门限）、无截断、无递归引用；聚合无分组、无分组集合、无去重、无过滤、全部为计数且参数只能为空、星字面量或被计数变量本身；显式写事务与组模式拒绝（只读、未绑定或普通 autocommit 上下文才放行；autocommit 单语句不可能持有暂存，早前语句已提交）；标签带有效存活期拒绝；标签不可解析拒绝。

执行期计数与扫描游标使用同一存活枚举原语，同一快照下两者天然一致，无需额外对账。

## 边门限

链条为聚合经裸透传投影直达已标注链尾计数的展开，且展开直接以纯源扫描（中间只允许扫描隐含的标签过滤）为唯一输入；展开为单边类型、非开放类型、单步、无过滤、无字面源、无采样、无连接输入、无路径语义、方向为出或入；源扫描标签缺省或等于边模式声明的对应端标签；聚合门限与顶点侧相同，被计数变量只能是边变量、目的变量、星或空。优化器识别被计数变量时同样放行星字面量，使边 `count(*)` 进入链尾计数路径。

执行期计数游走与种子驱动求和逐行等价：存活端点检查限定在被种子侧（出方向查源、入方向查目的），失效端计数行为与现有按块度数求和一致；悬空目的端计入，悬空源端排除。标签缺失按空扫描计零，类型缺失按零处理。

## 存储原语

新增两个面向查询的精确计数原语，与既有近似统计原语区分职责：

- 顶点按标签存活计数：复用扫描游标的存活枚举，含分片并行，不解码任何属性。
- 边按类型可见计数：先用存活统计判断端点表是否存在空洞，无空洞直接走可见性游走，有空洞则逐边附加端点存活检查，保证与种子驱动求和一致。

两者都拒绝存活期配置（执行期复核，防止构建与执行之间的模式竞态返回错误计数），都使用查询绑定的读快照与可见性门，保证与扫描看到同一快照。

## 明确不做

- 无方向展开不折叠，避免双向重复计数的语义争议。
- 属性计数（如计数某属性）不折叠，保持空值语义由慢路径处理。
- 分区装配路径不感知新源，启用分区时自动走原计划。
- 基数回填与并行通道仍按原计划延期，本阶段只保证解释输出对新源诚实。

## 验证

- 本地：新增端到端用例覆盖顶点计数、边计数、多路计数、星号计数（顶点与边）、种子变量回退、无方向回退、条件回退、分组回退、多跳回退、边类型存活期回退、顶点标签存活期回退、错配标签回退、删除顶点与删除目的端点后的精确性；既有展开列式、扫描身份、边身份、阻塞聚合、边度数用例全量通过（三个旧断言随计划升级为元数据标记，数值不变）。去重语法在方言中不可解析，门限保留为防御；标签不可解析时规划器先行报错，执行期缺失按空扫描计零。
- devs：复用探针流程对比五条计数查询，数值与改前一致，边计数进入低毫秒，顶点计数进入个位数毫秒。
- 回滚：新增源算子只在门限全满足时构建，任一门限收紧即自动回到原路径，无需数据迁移。
