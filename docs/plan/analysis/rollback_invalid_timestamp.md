# 独立分析任务：长序列事务 InvalidTimestamp

来源：docs/issue/rollback-bench-invalid-timestamp.md。
性质：契约厘清型任务，本轮不改代码。

## 已知事实

bench 按取时间戳、绑定上下文、写边、丢弃句柄、提交 staged、顺序提交的顺序执行，前数百次成功后在固定序号附近报槽位非 Pending；失败分支语义为槽位必须精确结算一次。

## 待确认事项

丢弃事务句柄的隐式中止是否提前结算了槽位；staged 提交与顺序提交之间是否存在重复结算；写状态映射的水位回收是否会清理 Pending 槽位。需复跑抓回溯并在失败分支记录槽位终态。

## 决策后实施方向

若为 bench 误用则修正 bench 顺序并文档化顺序契约；若为回收语义则修 MVCC 层保证 Pending 槽位不被提前回收。

## 实施结论（2026-10-10）

根因为库侧 edge 行写提前结算共享时间戳叠加 bench 侧同戳 double settle（见总纲第四阶段）；524 系 setup 消耗后的首个显式事务戳。落地：edge 在线路径结算门控、bench 分事务测量、契约文档化、回归测试。

## 验收口径

长序列 staged 加手工顺序提交路径稳定完成；契约以文档形式明确。
