# 客户端 / CLI / 前端集成缺口整改方案

配套现状结论：传输客户端（`linkrs-client` 的 HTTP 与 gRPC 双通道）与 CLI 已基本对齐服务端；缺口集中在三处——OpenAPI 契约文档漏注册了五个已实现的路由、前端服务层未封装已在契约中的端点、GPUI 桌面端缺整块管理域服务。本文档是本次整改的任务依据，描述只用自然语言，不贴完整代码。

## 背景与根因

服务端路由、注解、文档三者由 `openapi.rs` 中的一致性测试锁定。现状是五个已有 `utoipa` 注解的路由没有登记进文档聚合根，导致生成的 `frontend/openapi.json` 与 `schema.d.ts` 从源头缺失对应路径，前端类型客户端写不出调用；与此同时前端服务层对契约中已存在的向量数据面、全文检索、保存点等端点没有封装，页面只能绕行 GQL 或缺功能；GPUI 端则整块缺失同步、迁移、传输三个域的服务模块，事务服务也只覆盖了提交回滚主干。

本次不改服务端行为、不改 proto 契约、不新增传输协议，全部是消费侧补齐。CLI 经核查已完整，不动。

## 任务一：补齐 OpenAPI 文档注册

把会话变量查询、会话变量设置、会话变量删除、运行查询列表、运行查询终止这五个已有注解的处理函数登记进文档聚合根，使其进入快照。之后用仓库既定刷新命令重生成前端快照，再用既有代码生成工具重生成前端类型定义。验收以文档一致性测试通过为准，该测试同时校验路由与注解、注解与文档两组集合相等，快照比对一致，且操作标识符无重复。

## 任务二：补齐前端服务层封装

在既有服务模块内按原有风格追加方法，不新建服务体系，不新增页面文案以免触发国际化检查：

- 向量服务追加检索、计数、滚动、单点读取、载荷设置、载荷合并、载荷删除；
- 全文服务追加索引列表与检索；
- 事务运维服务追加保存点的创建、列表、回滚、释放；
- 会话服务追加会话变量的查询、设置、删除；
- 查询服务追加运行中查询的列表与终止；
- 统计服务追加单会话统计、冻结统计、冻结触发、迁移统计。

每个新增调用若被覆盖率检查脚本扫描到，必须在模拟处理器中同步补一条对应条目，否则模拟覆盖率检查会失败。流式与文件传输类端点按既有惯例走服务内模拟，不进通用模拟注册表。

## 任务三：补齐 GPUI 桌面端服务

遵循既有每个服务一文件的按域划分，只改消费侧薄封装，不碰服务端：

- 事务服务追加列表、终止、指标、重试输出箱，以及保存点的创建、列表、回滚、释放；
- 向量服务追加载荷设置、载荷合并、载荷删除；
- 新增同步服务，覆盖状态、诊断、死信、重排、重试、降级区间查询与清理、留存状态与执行；
- 新增迁移服务，覆盖计划创建、执行、回滚、试运行、历史、状态与进度流；
- 新增传输服务，覆盖服务端导入、导入状态查询与服务端导出；
- 查询服务追加运行中查询的列表与终止，会话服务追加会话变量的查询、设置、删除。

新增模块要在服务注册表中登记。验收为 GPUI 独立工作区的编译检查通过。

## 任务四：收尾验证

合并验证，禁止在修改过程中穿插编译。全部改完后集中跑四组检查：服务端文档一致性测试与快照比对、客户端与服务端相关单测、前端模拟覆盖率检查、GPUI 工作区编译检查。所有编译输出先重定向到文件再阅读过滤，不直接刷屏。
