# 第四阶段细化方案：更新语义收敛

本文是分阶段方案中第四阶段的细化实现说明，内容覆盖整属性映射覆盖
与会话配置设置形态评估。实现部分只做映射覆盖；
配置设置形态只做评估并记录结论，不新增语法。

## 1. 现状与目标

当前集合赋值仅支持逐属性赋值，每个赋值项描述单个属性的写入。
参考项目支持将整个属性映射一次性覆盖，
即以变量整体作为写入目标、以映射字面量作为写入值。

当前独立配置更新语句已覆盖模块加配置名加表达式值的形态，
与参考项目的查询内配置设置调用在功能上部分重叠。
本阶段不对配置语法做任何改动，只输出评估结论。

映射覆盖的目标是：解析器能够识别整体覆盖形态，
绑定与规划层将其标记与透传，执行器按覆盖语义替换整组属性，
而非逐项合并。空映射的语义明确为清空该实体的全部属性，
并在用户文档中写明。管道内的变量赋值本身已是覆盖语义，
无需改动，仅需在文档中说明其与存储写入覆盖的区别。

## 2. 覆盖形态的判定与约束

覆盖形态的判定条件为：赋值左侧为裸变量，
右侧为映射字面量。两侧条件缺一不可：
左侧为属性路径的形态仍走逐属性赋值；
右侧为非映射表达式的形态仍走普通变量赋值。

判定在解析赋值项时一次完成，并以标记形式存放在赋值结构中，
后续各层只透传标记，不再重复推导。这样可以保证
绑定、规划、执行三层对同一语句的理解一致。

合并语句中的创建与匹配分支子句复用同一赋值解析入口，
因此自动获得覆盖形态识别能力，无需单独处理。
形状缓存渲染遇到覆盖标记时跳过缓存，
因为字面量对象目标与映射整体语义无法用现有模板稳定表达。

## 3. 各层改动

抽象语法层面在赋值结构中新增覆盖标记字段，
默认关闭，仅当判定条件命中时打开。
所有构造该结构的位置需要同步补充默认值，
以保持编译一致性。

绑定层在绑定赋值结构中新增对等的覆盖标记字段，
逐项透传，不做语义改写。绑定失败的错误行为保持不变。

规划层在顶点与边更新信息中新增替换标记字段。
构建更新信息时，若该语句的任一绑定赋值携带覆盖标记，
则将替换标记置位。直接顶点更新、标签批量更新、
边更新、合并分支更新等所有构造更新信息的位置
都需要按此规则处理，保持语义统一。

执行层在更新顶点与更新边的写入算子中处理替换标记：
未置位时保持现有合并行为，即保留已有属性并叠加新属性；
置位时直接采用新属性集合作为最终属性，不再与旧属性合并。
空映射置位时自然产生空属性集合，即清空语义。
插入分支的创建路径不受替换标记影响，
因为创建本就是全量写入。

管道变量赋值算子的覆盖说明已存在于注释中，
本阶段不改动其行为，仅确认其与存储覆盖的差异已在文档中表述清楚。

## 4. 会话与扩展配置设置形态评估

评估对象是参考项目的查询内配置设置调用，
对比对象是当前已有的独立配置更新语句。

评估结论为语义完全重叠，不新增语法，理由如下：

- 当前独立配置更新语句已支持无模块与带模块两种形态，
  配置值接受完整表达式，覆盖了参考项目逐项配置的能力。
- 参考项目的查询内调用在当前项目中有对等的独立表函数调用语句，
  函数调用与配置设置职责分离，混合到同一调用入口反而模糊语义。
- 配置写入走直接的写路径分类，与查询内只读调用的路径不同，
  若新增查询内配置形态，需要改动读写路径划分，风险大于收益。

文档对应关系为：参考项目的逐项配置调用对应当前独立配置更新语句；
参考项目的表函数调用对应当前查询内函数调用语句。
该对应关系写入用户文档后，本评估项即视为关闭。
若未来出现查询内独有的配置语义，再单独立项。

## 5. 测试与验收

解析单测覆盖：逐属性赋值保持不变、裸变量加映射识别为覆盖、
属性路径加映射不识别为覆盖、裸变量加非映射不识别为覆盖、
空映射识别为覆盖。

写入后读取一致性用例覆盖：顶点标签批量更新的覆盖与合并对照、
指定顶点更新的覆盖与合并对照、边更新的覆盖与合并对照、
空映射清空行为、合并语句匹配分支的覆盖行为。
每个对照用例需要分别验证覆盖前后的完整属性集合，
而不仅是被写入的属性项。

配置评估的验收物为本细化文档第四节结论，
以及用户文档中的两种写法对应关系说明。

## 6. 风险与回退

主要风险是写入行为变更：同一语句在覆盖与合并语义下
会产生不同的最终属性集合。通过创建分支与匹配分支分离用例、
覆盖与合并对照用例进行控制。

回退方式为 revert 赋值标记的解析产生逻辑，
并将执行器的替换分支恢复为无条件合并。
由于标记默认关闭，回退后已有逐属性语句的行为完全不受影响。
