# GPUI 客户端国际化问题清单与整改方案

> 范围：`crates/linkrs-gpui/src/i18n.rs`、`crates/linkrs-gpui/messages/*.json`、
> 全部面板与登录视图的文案调用、语言切换响应链。
> 状态：第一批整改已落地并随常规门禁核验；文末列出有意保留的英文与后续工作。

## 1. 完整问题清单

### 1.1 词典被非文案噪音污染（最严重，已整改）

`messages/en.json` 与 `zh.json` 各有 652 条，其中约 82 条不是界面文案，
而是全量字面量扫描灌入的噪音：后端列名与协议字段、SQL 片段与查询语句、
日志与断言文本、测试数据、单字母与空白键。英文值多为首字母大写改写，
中文值多为机器乱翻，存在重复键（后写覆盖前写，静默生效）。
该污染直接破坏了既有单测中未知键回退的断言，并让覆盖率指标失真。

### 1.2 多参数模板只能填一个槽位（已整改）

格式化查询只替换首个花括号占位符，携带两个及以上参数的模板被迫在调用方
链式追加替换。跨语言语序无法调整，漏填时界面直接露出花括号原文。

### 1.3 缺键静默回退掩盖翻译缺失（已整改）

两个真实调用键在词典中缺失，界面回退显示英文键名，无任何门禁告警。
另有占位提示、表单标签、校验提示等约五十处界面文案以硬编码英文写在视图中，
集中在模式面板，另散见于数据浏览、控制台、传输与过滤条。

### 1.4 成功提示的中英混排（已整改）

模式面板与数据浏览的行写操作以英文动词拼接英文后缀组成成功提示，
中文下呈现半英半中。向量与全文面板已使用公共完成模板，行写路径未统一。

### 1.5 语言切换后部分面板不重渲染（已整改）

十个面板的构造器未订阅全局应用状态，切换语言后仅头部刷新，
各面板保持旧语言，直到下一次自身交互才更新。

### 1.6 输入框占位提示在切换时不刷新（已知局限，未改）

占位提示在输入框实体创建时一次性写入，重渲染不会重建输入框实体，
因此切换语言后占位提示保持旧语言，重启或重建面板后恢复正常。
根治需在语言切换时重建输入框实体，改动面大，留待后续。

### 1.7 键名无类型约束（部分缓解）

查询键为自由字符串，拼写错误只在运行时回退显示键名，编译器不拦截。
本次以命名空间断言单测约束增量，编译期类型化键名留待后续。

## 2. 修改方案与落地记录

### 2.1 词典清洗

仅保留命名空间点分键，允许的命名空间为界面十九个既有分组加过滤条分组，
其余无点键与越界点分键全部删除，重复键随重写自然去重。
补齐两处缺失键，补齐模式、数据浏览、控制台、传输、过滤条新增键，
中英双文件键集合保持完全一致。

### 2.2 查询接口升级

格式化查询保留单参数形态并委托到公共多参数实现，
新增按序填充任意数量占位符的查询，模板剩余槽位保持花括号可见。
全部链式追加替换的调用点迁移到新查询，模板内不再出现调用方二次替换。

### 2.3 门禁增强

在既有解析、孤儿键、抽查三项断言之外，新增多参数按序填充断言
与词典键命名空间断言，新增键纳入双语一致性检查。

### 2.4 响应链补齐

十个缺订阅面板在构造器入口订阅全局应用状态并请求重渲染，
与已有面板的订阅形态一致。

### 2.5 文案入库

模式面板的校验提示收敛为一个拒绝提示辅助方法，任务动词、表单标签、
占位提示、状态栏、空状态、错误映射全部入库。
数据浏览的行写成功提示统一使用公共完成模板，记录标题与覆盖保存按钮入库。
控制台多语句汇总与校验标题入库，传输格式占位与过滤条占位入库。
错误原文、SQL、路径、数字、协议字段等非界面内容一律不入库。

## 3. 附带修复

命令面板的目标筛选函数在界面文案入库时引入上下文参数，导致单测无法编译。
本次将能力过滤抽为纯函数，面板构造复用其结果，单测覆盖纯函数，
生产与测试共用同一顺序与过滤真相源。

## 4. 有意保留的英文

自动路由决策注记保留英文，因其内嵌技术选型关键词且有单测依赖关键词断言。
列名、空值标记、代码类型的默认值、索引类型字面量属于数据而非文案，不翻译。
示例性占位中的路径、查询语句、数字保持原文，仅描述部分翻译。

## 5. 后续工作

输入框占位提示随语言切换重建；键名编译期类型化或生成器校验；
复数与数字本地化格式；翻译缺失告警由回退可见改为门禁失败。
