# 前端剩余开放点后续决策与任务细化

> 承接《前端体验改进方案》第 11 章列出的 6 个待拍板开放点。本文逐项给出决策结论与后续任务的细化修改方案，范围以 `frontend/` 为主，涉及契约与种子数据的任务包含后端联动说明。文档中仅用自然语言描述行为与文件范围，不粘贴完整代码。

## 0. 目的与范围

把检索契约分歧、检索页形态、大图渲染、首页轮询、示例数据集、端到端测试这 6 个悬而未决的问题收敛为可执行任务。总体原则：能复用现有模块的不新建模块，能在原模块内改的不另起替代模块；不做向后兼容，契约以修正后的形状为准。

## 1. 决策总览

| 开放点 | 决策 | 一句话理由 |
|---|---|---|
| 索引列表契约声明 `string[]` 与实际对象数组不一致 | 修正契约，返回对象数组 | 后端、网关、前端展示都需要详情字段，字符串列表是信息丢失的形状，修契约比长期容错更彻底 |
| 检索测试场是否升格为独立一级页面 | 维持数据浏览器标签页，不建独立页 | 当前检索按空间维度组织，独立页会拆散信息架构，收益不足以抵消导航与状态重复成本 |
| 大图渲染策略 | 只做轻量分级优化，不引入 WebGL 双引擎 | 现有画布满足常规规模，大图靠截断与简化模式即可可用，引入新渲染引擎的事件与布局迁移成本过高 |
| 首页轮询 | 首页复用监控 store 的共享数据，不再直调接口 | 监控页已有轮询加流式推送，首页另起请求会造成双份请求与状态不一致 |
| 示例数据集一键载入 | 后端先提供种子接口，前端再接空状态入口 | 前端无法凭空造出有意义的图数据，必须先有后端幂等种子能力 |
| 组件级端到端测试 | 引入最小冒烟集，不追求全覆盖 | 模拟层已就绪，冒烟集能守住主链路，全量用例维护成本当前阶段不划算 |

## 2. 现状事实

- 索引列表链路：后端 `handlers/vector.rs` 的列表响应体携带字符串数组与计数，核心层 `VectorApi::list_indexes` 同样只返回名称集合；向量同步层的包装结构里实际保有空间编号、标签名、字段名与集合名；详情接口返回的 coordinated 信息包含集合名、向量数、索引向量数、点数、向量维度与距离算法。网关列表返回的详情远比 HTTP 列表丰富，前端 `services/vector.ts` 因此把载荷声明为未知类型，展示层靠运行时形状分类同时兼容字符串数组与对象数组，模拟层 `mock/handlers/management.ts` 返回的是对象数组。
- 命名分歧：模拟载荷用 `point_count`，后端详情结构用 `points_count`，两者指同一含义。
- 契约更新机制：`http/openapi.rs` 内含快照一致性测试，设置环境变量后运行指定测试可刷新 `frontend/openapi.json`，前端经由 `tools/openapi-codegen` 的生成脚本产出类型。
- 检索页现状：数据浏览器页内有顶点、边、向量、全文四种标签，标签状态由 `dataBrowserStore` 持有，检索面板通过属性传入当前空间。导航单一来源 `config/navigation.ts` 中没有独立检索路由，首页快捷入口指向数据浏览器。
- 图渲染现状：画布组件约两百行，围绕实例创建、元素同步、布局应用展开；图 store 的写入与合并入口均无数量上限；简化模式、过滤、高亮已存在；布局参数与耗时展示已接入指标。
- 首页与监控：首页在挂载时一次性拉取数据库总览，失败时静默降级；监控 store 持有全量快照，以 10 秒轮询为主、2 秒流式推送为辅，流推送的总览中已内嵌系统与数据库分片，具备启停与暂停能力。路由同一时刻只挂载一个页面。
- 种子数据：服务端无演示种子接口，传输服务仅支持文件导入与服务端导出重演；各空状态只有文字提示，无一键载入入口。
- 测试：工具函数有 `node:test` 单测，检索分类与命令过滤已有用例；无浏览器级测试框架，模拟模式支持以查询参数切换慢速、错误、空数据场景。

## 3. 逐项决策与理由

### 3.1 索引列表契约修正

字符串数组无法表达空间、标签、字段、维度、距离、状态与点数，详情页、运维排查、前端表格都需要这些字段，保留字符串主路径只会让三端长期各说各话。网关侧已证明详情可取，HTTP 侧没有理由继续降级。决策为把列表响应改为对象数组：复用已有的索引信息结构并补齐空间、标签、字段三元组，计数保留。旧的字符串形状不再兼容，前端与模拟层同步切换，展示层的形状分类保留为兜底显示手段，不再作为主路径依赖。命名统一为 `points_count`，模拟层跟随改名。

### 3.2 检索页维持标签形态

独立检索页的典型诉求是跨空间统一搜索与命中直达画布。当前向量与全文检索均要求先选定空间，统一搜索的后端能力不存在；命中结果虽有文档编号与载荷，但按顶点编号直达画布的链路尚未打通。此时新建一级路由只会复制空间选择、标签切换与结果表格三套状态，还要处理与数据浏览器的入口重复。决策为不建独立页，改为补齐深链接与命中直达：标签页支持以查询参数直达向量或全文，检索命中提供在图中查看的操作，把现有链路做完整。若未来出现跨空间统一检索，再重评估独立页。

### 3.3 大图只做分级优化

双引擎方案需要引入新的 WebGL 依赖，重写点选、框选、缩放、布局、样式与事件体系，且两种引擎的视觉与交互一致性难以保证。实际大图场景的首要诉求是页面不卡死、用户知道数据被截断、能快速定位关键节点，这些靠上限截断、默认简化、标签隐藏与按规模选布局即可满足。决策为在现有画布与图 store 内做分级优化，不新增渲染依赖。性能验证若证明常规交互确实需要数千节点全量可操作，再单独立项评估 WebGL。

### 3.4 首页复用监控 store

首页与监控页消费的是同一份数据库总览。首页直调意味着每次回首页都多一次请求，且与监控页的轮询节奏脱节；监控 store 已是单例，内含轮询、流推送、暂停、阈值与错误保留语义，直接复用最省。决策为首页改为订阅监控 store 的数据库分片：有缓存即渲染，无缓存显示骨架屏，失败显示不可用提示；挂载时启动共享刷新，卸载时停止。因路由独占，启停对称即可，无需引用计数。

### 3.5 示例数据集分两步走

一键载入的本质是后端幂等种子能力，前端按钮只是触发器。没有种子接口时前端只能伪造数据，演示价值低且与真实链路脱节。决策为后端先行：新增管理员鉴权的种子接口，创建演示空间、标签、边类型、若干顶点与边，并按需建向量与全文索引；已存在时直接返回存在，不重复写入。前端随后在首页快捷区、数据浏览器空提示、架构页空提示接入统一入口，模拟模式同步提供成功载荷。接口契约先定，实现排期另议。

### 3.6 端到端测试只做冒烟集

模拟层已覆盖登录、查询、架构、浏览、监控等主链路，缺的是浏览器驱动与用例组织。决策为引入最小冒烟集：驱动本地模拟服务，覆盖登录、控制台查询、视图切换、数据浏览器渲染、监控渲染与命令面板跳页，辅以错误与空场景各一条。全量交互覆盖暂不做，单元测试仍是主力，冒烟集只守主链路不因重构频繁失效。

## 4. 细化修改方案

### 4.1 契约修正任务

目标：列表接口返回对象数组，三端一致。

- 后端列表处理器：将响应体中的字符串数组改为索引信息数组，逐项填入集合名、空间编号、标签名、字段名、向量维度、距离算法、点数与状态；计数语义不变；鉴权保持管理员要求。详情结构与列表元素保持字段同名同义。
- 核心层：列表方法在返回名称集合之外，新增返回详情集合的能力，供处理器组装，避免处理器直接穿透到底层协调器。
- 契约刷新：运行快照一致性测试刷新 `frontend/openapi.json`，再运行前端类型生成脚本更新 `schema.d.ts`。
- 前端服务层：将向量列表方法的返回类型由未知收窄为对象数组，字段按新契约命名；详情方法保持不变。
- 展示层：结构化载荷组件以对象表格为主路径，字符串数组仅保留为历史兜底显示；模拟层列表载荷改用新字段名并与契约对齐。
- 国际化：无需新增文案，字段名沿用现有检索词汇。
- 测试：后端补充列表形状断言；前端补充分类器对信封解包与空数组的既有用例即可，无需新增框架。
- 验收：模拟与真实两种形状均渲染为表格；类型生成后无手动补丁；快照测试通过。

### 4.2 检索页增强任务

目标：不新增路由，深链接与直达画布可用。

- 标签深链接：数据浏览器页读取查询参数决定初始标签，标签切换时回写查询参数，刷新与分享链接可直达向量或全文。
- 命中直达画布：向量与全文结果行增加在图中查看操作，携带空间、编号与载荷跳入图工作台；图工作台按编号选中并居中，复用既有定位逻辑。
- 导航：导航单一来源不新增条目，命令面板自动继承深链接目标；首页快捷入口保持指向数据浏览器，不新增检索入口。
- 国际化：新增深链接无感知文案，仅补直达操作与失败提示的中英双语。
- 测试：补充标签参数解析与命中转图参数组装的纯函数用例；模拟模式下走查向量与全文标签直达。
- 验收：以带参链接进入可定位到对应标签；命中行可跳画布并选中；无新增一级路由。

### 4.3 大图分级优化任务

目标：大图不卡死、可感知截断、可操作。

- 图 store：在写入与合并入口增加节点与边上限，超限时按当前查询顺序截断并记录总数与是否截断；清空与重置逻辑不变。
- 画布：按元素规模选择布局策略，小规模用力导向，大规模用网格或预设；缩放层级低于阈值时隐藏节点文字标签，仅保留图形；批量同步保持不变。
- 图工作台：在画布角落展示总数与截断提示，简化模式在大规模时默认开启但允许手动关闭；搜索命中清单上限保持不变，标题显示全量数。
- 国际化：新增总数与截断提示文案的中英双语。
- 测试：补充截断计数与布局策略选择的纯函数用例；模拟大图数据走查帧率感知与提示可见性。
- 验收：数千节点导入不阻塞交互；截断提示可见；标签隐藏与简化开关行为符合预期。不引入新渲染依赖。

### 4.4 首页复用监控数据任务

目标：首页与监控页同源，零多余请求。

- 首页：移除直调数据库总览的逻辑，改为订阅监控 store 的数据库分片；挂载时启动共享刷新，卸载时停止；加载态沿用骨架屏，失败态沿用不可用提示。
- 监控 store：确认启动与停止幂等，流中断时轮询兜底不受影响；首页只消费数据库分片，不改动其余分片逻辑。
- 国际化：无新增文案。
- 测试：补充首页在有缓存、无缓存、失败三种状态下的渲染分支用例；走查首页与监控页往返切换无重复定时器。
- 验收：回首页不产生额外总览请求；断流与断网下降级行为与现状一致。

### 4.5 示例数据集任务

目标：空状态可一键获得可玩数据，接口幂等。

- 后端：新增管理员鉴权的种子接口，创建演示空间与配套标签边类型，写入数十量级顶点与边，条件创建向量与全文索引；重复调用返回已存在，不报错不重复写；操作留痕便于清理。
- 前端：在首页快捷区、数据浏览器空提示、架构页空提示接入统一载入入口，载入中禁用按钮并显示进度，成功后刷新空间列表并引导至数据浏览器。
- 模拟层：提供种子成功与已存在两种载荷，覆盖按钮全链路。
- 国际化：新增载入、载入中、已存在、失败重试四组中英双语。
- 测试：后端补充幂等断言；前端补充入口可见性与状态机用例。
- 验收：空环境一次点击可浏览演示图；二次点击不产生重复数据。本任务依赖后端排期，前端入口可先按契约并行开发。

### 4.6 冒烟端到端任务

目标：主链路有浏览器级守护，维护成本可控。

- 框架：引入浏览器测试运行器与 Chromium 驱动，配置启动本地模拟服务；测试脚本独立于单元测试脚本。
- 用例：登录进入控制台并执行查询、结果视图切换、数据浏览器标签渲染、监控页渲染、命令面板打开并跳页，共五条主链路；错误场景与空场景各一条。
- 数据：全部走模拟层，不依赖真实后端；场景切换沿用查询参数。
- 文档：补充运行说明与常见失败排查。
- 验收：冒烟集在本地全绿；纳入手动发布检查表，暂不强制接入持续集成，稳定后再议。

## 5. 验证方式

- 前端：国际化完备性、设计令牌、类型检查、模拟覆盖四项检查通过；单元测试通过；代码规范检查通过；模拟模式下按慢速、错误、空场景走查检索、首页、图谱与种子入口。
- 后端：契约快照测试通过；种子接口幂等测试通过；向量列表形状断言通过。
- 浏览器：冒烟集在 Chromium 下全绿。

## 6. 不做事项与后续观察

- 不新建独立检索路由，不新增渲染引擎依赖，不为旧字符串列表保留兼容分支。
- 大图若在真实业务数据下仍卡顿，收集节点规模、布局耗时与交互帧率后再评估是否单独立项。
- 示例数据集的清理接口与多套演示模板暂不做，待种子接口落地后按需追加。
- 端到端覆盖率暂不设指标，先保证冒烟集稳定，再按故障复盘逐步补齐。
