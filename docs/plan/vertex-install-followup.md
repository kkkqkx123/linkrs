# 顶点表安装与同步点：后续阶段分析

## 现状与证据

全量导入 11.4 秒，提交段合计约 5.1 秒。顶点语句提交约每行 6 微秒
（21.5 万行约 1.3 秒），边语句约 0.4 到 0.7 秒（无表安装，只有 WAL
追加与同步点）。提交段剩下的工作分三类：顶点表逐行装入、WAL 追加、
每语句同步点（一次全局同步加逐分区表日志横扫）。

逐行装入（`apply_staged_inserts` 经 `apply_insert`）每行必经：分片路由、
时间戳写锁加待定标记、主键索引条带锁探测与绑定、逐列模式检查与列柄
查找、版本写入、时间戳写锁发布，外加提交映射的一次外部标识格式化
（批量窗口已跳过）与领域观测。预检（`prevalidate_staged`）在纯插入
场景下只剩一次全量已建集合构建，其余分支全空。

同步点是 Sync 语义的最低线：每语句一次全局 WAL 同步与分区横扫，一个
不能少；脚本级合并提交只能省同步点（百毫秒量级），却把语句级原子性
改成全有或全无，已否决，不再讨论。

## 正确性契约（任何重写必须遵守）

- 读者永远看不到半行：待定标记先行，列数据就位后才发布创建戳。
- 预留绑定精确报错：键已绑定（存活或待回收墓碑）与预留不匹配即整组
  失败，错误语义与逐行路径一致。
- 中途失败全组补偿：已装入前缀按逆序撤销、未装入预留全部释放、
  时间戳中止；内存已装入与 WAL 已落盘必须同生共灭，追加失败即撤销
  已装入行。
- 唯一约束不弱化：主键重复在装入时仍逐键判定，预检的豁免只针对本
  事务自建行。

## 子项（按期望价值排序，各自独立可回滚）

### 零、提交段再分段计时

把提交段拆成装入、WAL 追加、同步点、时间戳四段，环境变量门控，
默认无输出。前面两轮都是先计时再动手确立优先级，本轮同样从测量开始。

### 一、锁存批量化

同一分片组内只拿一次时间戳写锁，批量标记待定、批量发布；主键索引
条带锁随键哈希自然分散，保持逐键判定与错误语义。失败补偿沿用已装入
向量，不动契约。预期省掉每行数次锁获取，改动局限在同一模块。

### 二、列柄按组记忆

装入组内逐行重复模式检查与列柄查找。按组解析一次，配合模式版本号
设防：版本号变化即回退逐行。需先审计模式管理器的版本计数是否存在、
并发 DDL 是否可观测；审计不通过则本项降级为不做。

### 三、预检已建集合懒构建

纯插入场景跳过全量已建集合构建，有更新或删除暂存时保持原样。
行为完全一致，几行改动，先做。

### 四、分片并行装入（深水区）

各分片组触及的分片锁天然不交，共享点只剩条带化主键索引、统一身份
分配器与提交映射。动手前必须完成审计清单：身份分配器的锁粒度、
预留释放的并发安全性、失败时跨分片补偿顺序、提交映射的合并方式。
多核收益最大，风险也最大，单独成项，最后做。

### 五、同步点即下限

每语句同步点是语义 floor，不再立项。内核不支持批量同步接口，
硬件换代前维持现状。

## 明确不做

- 装入推迟到检查点：已提交数据必须立即可读，推迟破坏提交语义。
- WAL 落盘格式改动：重放兼容性不动。
- 唯一检查跳过：正确性核心，无论批量大小一律逐键判定。

## 验证

devs 同基准：总耗时、提交段分段占比、九条查询行数与耗时；存储全量单测、
导入端到端、查询单测全过；并发读写混合用例（如有）重点回归。
任一回退即还原对应原模块文件。
