# 端到端列式扫描集成方案

本文档以前阶段分析基线为准：顶点列式批量读取已在存储层实现，执行器列块路径已存在但默认关闭，边侧尚无原生列式实现，过滤仍走布尔掩码加压缩的老路径。以下以自然语言描述目标、范围、步骤与验收，不含完整代码片段。

总体原则：正确性、可靠性、防误用优先于性能；只修改原模块，不新增替代模块；边与顶点的游标 trait 不做破坏式变更，默认转置回退保留到原生实现全部上线为止；全部编译与测试合并为尽量少的运行批次。

## 第一阶段：边原生列式批量

目标是让边扫描具备与顶点对等的原生列式批量能力，消除边列块路径对逐行转置回退的依赖。

范围限定在边游标实现与边属性读取路径，包括边列式批量的原生构造、边谓词在列式路径下的剪枝复用、边批量类型的装配。不涉及执行器算子改造与默认开关切换。

做法是先复用顶点已验证的装配思路：在边游标上按投影列直接从属性列解码出类型化批量，拓扑字段随行携带；谓词剪枝复用既有的边行块存活判断与全局边界短路，跳过不含活边的块后再解码；解码失败或类型混杂时逐列回退到通用表示而非整批回退到逐行，保持部分加速。顶点侧实现保持不动，只抽取可复用的装配约束作为边实现的对照。

验收以边存储列式单测为主：构造含多属性列的边表，对比原生列式批量与转置回退在内容上完全一致；构造含墓碑与谓词的扫描，检查剪枝后行数与逐行路径一致；类型混杂列检查回退列的内容正确。建议与第二阶段验收合并运行，减少编译次数。

风险在于边属性列与顶点列共享实现但生命周期不同（槽位回收、时间戳语义），原生解码必须经过与逐行路径相同的可见性门。应对是复用既有的行块存活与谓词匹配入口，不另写可见性判断。

## 第二阶段：消除执行器侧逐行物化

目标是让列块组装不再经过逐行中间表示，类型化列直接由存储批量构建。

范围限定在执行器扫描算子的列块组装函数，包括顶点与边两条组装路径的逐行物化消除、类型映射的空值表达补齐、内存记账调整。不涉及存储层解码逻辑变更。

做法是先明确组装的输出契约：下游算子同时消费行视图与类型化列的现状保留，本阶段只消除内部的重复物化——类型化列直接由存储批量转换，行视图按需延迟构建而非每次预建；空值表达补齐到类型化列自带的合法性位图，不再依赖哨兵值二次判断；内存记账改为按类型化列实际字节加行视图实际分配分别统计，避免重复计算。窄整型与单精度拓宽到执行器有完整求值支持的布局的现状保留。

验收以执行器扫描单测与端到端查询回归为主：在列块开关打开与关闭两种模式下运行同一批查询，检查结果行集一致；检查含空值的列在类型化路径与逐行路径下求值一致；检查内存记账在两种模式下都不出现重复放大。建议与第一阶段测试合并为一次存储加查询测试运行。

风险在于下游算子对行视图的隐式依赖。应对是本阶段保留行视图输出，只改变其构建时机与内部复用，不删除任何下游可观测的输出形态。

## 第三阶段：选择向量过滤与默认开启

目标是用选择向量替代布尔掩码加压缩的过滤表达，并将列块模式转为默认路径。

范围限定在存储批量过滤表达、顶点与边列式路径的谓词下发、列块开关默认值的切换与回滚说明。不涉及查询优化器的谓词推导变更。

做法是先在批量类型上引入选择向量表达：过滤产生索引序列而非掩码，跳过行的解码直接按选择向量裁剪；顶点与边各自的解码后残余过滤统一走该表达，调用方不再分别处理掩码语义；开关切换为默认开启，同时保留显式关闭的环境回滚手段并在文档中说明；列式命中统计保留，用于上线后观察实际命中率。开关切换前要求前两阶段验收全部通过。

验收以全量回归为主：默认开启后运行存储与查询的全部单测与集成测试，确认无结果差异；构造谓词选择性差异大的扫描，检查选择向量路径的行数正确且内存占用不高于掩码路径；演练一次显式关闭回滚，确认逐行路径仍可用。建议单独运行一次全量测试批次。

风险在于默认切换影响面最大。应对是切换只改默认值，不删除逐行路径；上线后以列式命中统计观察一周期的实际命中率，命中率异常时先回滚默认值再定位。

## 测试与落地顺序

三个阶段按顺序落地，前两阶段可合并验证，第三阶段独立验证。全程合并为两次左右的编译测试批次：存储加查询回归一次，全量默认开启回归一次。每批次附带格式化检查。每个阶段完成后更新对应的现状说明，使代码与文档保持一致。

非目标：查询优化器的谓词推导与连接顺序不受本方案影响；持久化格式与编码选择不受本方案影响；固定字符串改定宽布局已有保留结论，不在本方案内重议。
