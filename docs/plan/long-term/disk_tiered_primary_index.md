# 磁盘分级主键索引初步设计（后续参考，短期不实现）

## 现状

主键索引常驻内存，由条带化哈希、槽位表、存活集、空闲堆与增量日志组成，文本主键持有完整字符串。内存随行数线性增长，单机上限由内存决定。持久化采用全量基线与增量二选一，提交清单为唯一提交点。

## 目标与非目标

目标是将单机上限从内存转为磁盘，支撑超出内存的大标签，同时保持点查正确性与清单提交语义。非目标是不替换现有内存索引为通用外部引擎，不改变外部键路由与全局编号含义，不引入通用二级索引。

## 设计方向

热端保持现有内存条带与增量日志，承担写入与高频点查。冷端按分片落盘为有序键区间文件，承担全量与低频查询。冷热之间以驻留位图与代际水位划分，驱逐只移动稳定行，活跃行不下沉。点查先走热端，缺失再查冷端元数据后按需加载，避免全表扫描。后台合并沿用现有稳定回收与整理的水位思路，越线分片才做重排。清单仍只钉扎基线与增量 checkpoint，冷文件作为可重建派生数据，缺失可回退为常驻重建而非拒绝整表。

## 关键取舍

冷端命中必然增加一次磁盘访问，点查尾延迟上升。用布隆与区间元数据剪枝冷端访问次数，用常驻热集保证高频键不受影响。合并频率与写放大的平衡沿用现有水位线做法，小表不触发，大表分片级触发。

## 风险

冷热误判会导致抖动，需要驻留与命中指标先行。合并期间的崩溃恢复必须仍以清单为准，冷文件损坏只影响性能不影响正确性。恢复时间随冷文件数量增长，需要清单校验保持线性可读。

## 推进顺序

先补齐冷热划分指标与可观测性，再做只读冷端影子构建与一致性校验，最后才打开写入下沉路径。每一步都保留回退到纯内存的开关。
