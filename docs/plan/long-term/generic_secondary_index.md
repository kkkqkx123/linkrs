# 通用二级索引初步设计（后续参考，短期不实现）

## 现状

除主键索引外无通用二级索引，条件过滤依赖列扫描与区域概要剪枝。主键点查、批量导入、列扫描路径已收敛，清单仍为唯一提交点。

## 目标与非目标

目标是为高频过滤列提供等值与范围加速，同时保持与主表的提交一致性。非目标是不做全文检索的替代，不做跨标签联合索引的复杂优化器，起步不做多列复合二级索引。

## 设计方向

索引按列独立构建，形态按列类型选择有序结构，复用现有列存分块与区域概要的剪枝思路。索引更新随主写在同一请求作用域内暂存，随提交原子生效，后台合并复用稳定回收的水位做法。查询规划先做单列索引下推，命中则按主键回表，不过度设计多索引合并。索引文件纳入清单管理，缺失按列隔离语义处理，单索引损坏只降级该列加速而不拒绝整表。模式变更时索引随列增删而增删， pending 期间拒绝索引构建而非部分构建。

## 关键取舍

写放大换读加速是核心代价，高更新列不建索引应作为使用建议写明。回表成本决定索引收益，只有选择性足够的列才值得建，优化器需要选择性估计而非无条件使用索引。

## 风险

索引与主表一致性是最大风险，后台构建必须以检查点代际为准，错代构建必须丢弃重建。索引膨胀会显著增加检查点体积与恢复时间，需要配额与驱逐策略。部分可用被误用为完全可用需要通过明确错误与文档控制。

## 推进顺序

先做单列等值索引与回表下推，再做范围能力，最后才评估复合二级索引。每一步都保留关闭索引回退到扫描的能力。
