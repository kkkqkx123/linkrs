# 复合主键初步设计（后续参考，短期不实现）

## 现状

主键仅支持整数与文本两种形态，负整数拒绝，文本有长度上限。主键镜像列由类型转换承载，不可往返值在插入期直接失败。路由与条带哈希基于单键计算。

## 目标与非目标

目标是支持多列组合主键，保持点查、路由、索引、镜像列的一致语义。非目标是不做通用二级索引，不改变单键表的持久格式，不放宽单键的长度与形状校验。

## 设计方向

组合键的列顺序、空值处理、大小写与类型归一规则先行冻结，并在建表时校验。组合键编码为单一规范字节序列后，再进入现有路由与条带哈希流程，使分布与分片逻辑复用单键路径。索引键比较按列逐段进行，镜像列按成员列逐列存放并保持往返一致。干跑预检扩展组合键形状校验，非法组合在拷贝前拒绝。查询层的等值点查下推复用现有主键路径，范围查询仍走扫描与区域剪枝，不为此新增索引类型。

## 关键取舍

规范字节序列带来一次编码成本，但使路由、哈希、持久三层复用单键逻辑，避免三处各自定义组合语义。空值是否允许参与主键需要一次性决策，允许则复杂度显著上升，建议起步阶段拒绝含空组合键。

## 风险

归一规则变更会改变键含义，必须走重建。镜像列与外部形态不一致会在插入期失败，需要明确的错误指引。旧单键表不受影响，但新旧表的查询语义差异需要在文档中写明。

## 推进顺序

先冻结键规范化与校验规则并补齐单测，再做索引与路由的组合键接入，最后补齐查询下推与镜像列一致性。通用二级索引立项前应先复用本方向的形状规则。
