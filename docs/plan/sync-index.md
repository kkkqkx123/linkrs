## 三、分篇进度与剩余任务

### 3.1 向量后端一致性

已完成：协调器不再直触底层引擎，分组经索引管理器一次转换后调后端批量写入；发布与恢复按能力查询分支；两后端滚动流均为按需分页真流，检索流已如实注释为缓冲转发。

剩余：

* 索引管理器内的本地特化收敛到后端内：集合创建默认配置选择、空间粒度物理回收。
* 删除底层引擎逃生口的业务分支使用，保留构造期选择，调用期只走能力与语义接口。

易混淆：快道与投递仍需判断本地与远端，该判断属于部署形状选择，不属于本篇要消灭的后端内部分叉，不可混为一谈。

### 3.2 本地快道

已完成：数据面意图直接应用后写空提交标记推进前沿；模式变更与不可解码意图走发件箱；快道失败整批回退常规投递；提交包装饰器的显式与自动提交路径均接入最终提交入口。

剩余：

* 补组装期部署形状判定与启动日志明示，现状为每批动态判定，无日志。
* 对齐标记失败语义，现状仅记日志，设计要求视为提交失败的一部分。
* 补跨引擎可见性顺序说明。

易混淆：重建追赶仍从发件箱认领，不进快道；恢复回放走物化路径，不走快道直写。

### 3.3 运行时归属

已完成：组装入口显式注入运行时句柄，缺件在构造期报错而非恐慌；管理器持有后台投递任务句柄并随启停回收。

剩余：

* 收敛同步桥接：现状仍按环境探测并按次创建临时运行时，热路径成本未消除。
* 同步垫片去派生：投递并发只保留在异步核心内，垫片只做边界桥接。
* 协调器自持句柄随管理器统一分发，不再各自为政。

易混淆：本篇不改变投递语义与并发度，不对存储与服务层做大面积异步化，只收敛归属与方向。

### 3.4 配置收敛

已完成：删除忽略传入配置的兼容构造；服务组装期一次换算为投递策略与消费者配置，运行时只读换算结果并记日志。

剩余：

* 一物一主未完成：批量概念仍在三处并存，失败策略仍两套并存，只收敛归属不收敛语义。
* 旧全文批处理路径随旧写入范式退役，退役前只读不扩，另立项迁移测试用法。
* 确认外部配置文件未知键态度，倾向忽略加告警而非启动失败，现状为严格拒绝。

易混淆：本次只删误导性接口，不改任何默认值与线上行为，不合并语义不同的参数。

### 3.5 管理器拆分

已完成：发件箱按六职责分文件，管理器外观按七模块分文件，对外公有接口零变化。

剩余：

* 门面收薄：投递驱动独立持有管理器引用，重建编排持有索引管理器与发件箱引用，发件箱运维方法下沉发件箱自身，管理器只转发。
* 管理器结构体瘦身到双协调器、发件箱、接收器、运行标志与统计，背压与消费者配置随使用方走。
* 向量侧随问题驱动按归属搬移，不主动重排。

易混淆：本篇只拆文件与归属，不改变投递语义、重建语义与跨包接口，不做性能优化。

## 四、统一剩余任务顺序

1. 向量残留分支收敛，无公有变化，可独立合入。
2. 快道补启动日志与标记语义，需存储与事务侧确认。
3. 运行时桥接收敛，需服务与嵌入式两侧联调，选稳定窗口。
4. 配置旧路径退役单独立项，先迁测试。
5. 门面每次只搬一个职责并保持转发，分多步落地。
