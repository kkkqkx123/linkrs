# 同步配置收敛设计方案

本文是此前向量后端一致性整改中列入远期的第四项的展开。
只描述设计，不贴完整代码。实现时只改原模块，不新增替代模块。

## 背景

同步相关的可调参数散落在四处，归属不清。
同步配置结构体放在全文配置名下，
含队列长度、提交间隔、批量大小与失败策略四项，
却只有前两项被旧的全文批处理路径消费，
批量大小无人使用，管理器的兼容构造直接忽略整个结构体。
向量投递另有后端投递策略，含批量、租约、重试与并发，
注入时再换算为消费者配置，投递循环只信任后者。
背压、留存、旧批处理配置又各有其主。
同一个批量概念有三处数值，改一处而漏一处的分叉
只是时间问题；被忽略的构造参数则是对调用方的误导。

## 目标与非目标

目标：每个可调参数有唯一所有者，组装期一次换算，
运行时只信任换算结果，无人使用的参数不再出现于接口。
非目标：不改变任何参数的默认值与线上行为，
不合并语义不同的参数，不扩大配置包的依赖。

## 现状盘点

- 投递批量：同步配置的批量、投递策略的批量、
  消费者配置的批量三处并存。同步配置的批量只流入旧全文缓冲路径，
  发件箱投递实际生效的是消费者配置。
- 租约、重试、并发：只在投递策略与消费者配置中出现，
  全文投递复用同步层的失败策略，走另一套。
- 背压：独立成组，随管理器走，热路径只读。
- 留存：放在向量配置名下，与发件箱裁剪共用。
- 旧批处理：同步配置的前两项经一次转换流入旧全文缓冲路径，
  该路径本身已是待移除的旧范式。

## 设计

确立一物一主。配置包只保留纯数据旋钮并按职责分组：
投递组含批量、租约、重试、并发与失败策略；
背压组含单事务与全局上限；留存组含裁剪周期与位点距离。
全文名下的同步配置不再作为通用同步配置存在。
本次只删除具有误导性的兼容构造，
配置结构体本身保持不动：其批量与失败策略仍被旧全文缓冲路径消费，
随该旧路径退役而删除，不在本次执行。

组装期一次换算。服务与嵌入式组装入口把纯数据配置
换算为运行时的投递策略与消费者配置各一份，
此后运行时只读换算结果，不再回头解释原始配置。
投递策略仍是调优的唯一入口，消费者配置仍是投递的唯一依据，
两者之间的换算函数是唯一的数值来源。

删除误导性接口。管理器的兼容构造若忽略传入的配置，
就改为不接受该参数，调用方随之精简。
任何构造器不允许出现以下划线开头的被忽略参数，
缺省用默认值显式表达，而不是用忽略表达。

旧批处理路径随旧全文写入范式一并退役，
退役前其配置只读不扩，退役后相关转换一并删除。
该退役需先迁移全文包的测试用法，单独立项，
不在本方案内执行。

## 验收

- 每个参数名在配置包中只出现一次，无同义重复。
- 投递循环与热路径的数值来源唯一且可追溯到组装期换算。
- 无被忽略的构造参数，无以下划线开头的配置形参。
- 默认行为与线上表现零变化。
- 旧路径退役立项有明确前置条件与迁移清单。

## 风险

- 参数删除看似无行为变化，但外部配置文件可能仍在填写旧键，
  需确认反序列化对未知键的态度，倾向保留未知键忽略加告警，
  而非启动失败。
- 失败策略合并涉及全文与向量两套语义的统一，
  统一前保持两套并存，只收敛归属不收敛语义。
- 换算函数成为单点，需单测覆盖默认与边界换算。
