# 第三阶段细化方案：导入扫描源扩展

本文是分阶段方案中第三阶段的细化实现说明，内容覆盖导入扫描源扩展。
约束保持不变：只修改原有模块，不新建替代模块；选项值维持字符串字面量约束。

## 1. 现状与目标

当前导入读取语句仅支持文件与通配文件两种来源。
扫描源枚举中已存在表函数变体，但解析器从不产生该变体，
因此规划器与执行器中的表函数分支实际不可达。

参考项目支持的来源还包括列定义头、查询结果作为扫描输入，
以及文件列表、参数、附库表等形态。
本阶段只收敛到四种来源：文件、通配、表函数、查询，
外加可选的列定义头子句。文件列表、参数、附库表不在本阶段实现，
解析到这些形态时必须返回明确错误，不得静默产生空结果。

目标语句形态为：在加载关键字之后允许出现可选的列定义头子句，
然后是来源描述，之后保持已有的选项子句与返回子句。
列定义头用于声明列名与列类型提示；查询来源允许括号包裹的完整查询
作为扫描输入；表函数来源允许函数名加括号参数表的形态。

## 2. 语法与语义约定

列定义头为可选子句，写在来源之前，包含一至多个列定义，
每个列定义由列名与可选的类型名组成。类型名仅作声明与透传，
本阶段不做严格类型校验，执行侧统一按字符串读取。

来源判定顺序为：通配关键字形态优先，其次为左括号起始的查询形态，
其次为标识符加左括号的表函数形态，最后为字符串字面量的文件形态。
括号查询与表函数调用在首词元上有重叠，因此解析器需要按上述顺序
依次尝试，避免把查询误判为表函数。

查询来源的语义是复用子查询物化链路：内层查询先独立规划，
外层加载语句不再产生独立的扫描节点，而是直接返回内层计划。
外层选项中的分隔符、头部开关等文件专属配置对查询来源无意义，
遇到时规划器直接拒绝并给出明确错误，而不是忽略。
外层列定义头若存在，则作为列重命名提示作用于内层输出；
列数不一致时同样拒绝并报错。

表函数来源的语义是复用查询内函数调用链路：
参数按表达式求值后传给表函数注册表，未注册的函数名直接报错。
选项子句保持原有键值形态，不新增选项类型。

空结果与错误的区分原则为：通配未命中文件、未知表函数、
查询来源规划失败、列定义与实际输出列数不一致，
一律返回明确的执行或规划错误；只有正常命中的空文件才允许返回空结果集。

## 3. 解析层改动

抽象语法层面需要在加载语句结构中新增列定义头集合字段，
并在扫描源枚举中新增查询变体，变体内部持有完整的内层语句。
列定义结构包含列名与可选类型名，复用已有的标识符解析能力即可。

加载语句解析函数需要调整为先识别可选的列定义头，
再按判定顺序识别四种来源。表函数参数解析为表达式列表，
括号查询通过递归调用顶层语句解析入口完成，
内层查询的括号必须闭合，失败时按语法错误处理。

返回子句与选项子句的解析保持不变。
选项解析继续只接受字符串字面量作为值，不引入新的选项类型。

解析单测需要覆盖：无头文件形态、通配形态、表函数形态、
查询形态、带列定义头的各来源组合，
以及错误形态如空列定义、未闭合括号、未知来源关键字的拒绝行为。

## 4. 绑定与规划层改动

绑定器当前对加载语句采用透传处理，本阶段保持不变，
内层查询语句的绑定推迟到规划阶段随内层规划自然完成。

规划器对加载语句的处理需要按来源分支：

- 文件与通配来源保持现有扫描节点构造方式，
  列名推导优先级调整为列定义头优先，其次为返回子句别名。
  当列定义头存在时，即使文件自带表头，输出列名仍采用声明的列名。

- 表函数来源保持现有扫描节点构造方式，
  列名推导同样遵循列定义头优先原则。

- 查询来源不再构造扫描节点，而是用内层语句重新选择规划器
  并调用其转换入口得到内层子计划后直接返回。
  构造内层已验证语句时复用外层的表达式上下文与验证信息，
  因为内层语句与外层在同一解析上下文中产生。
  若内层没有可用规划器，或外层携带了仅适用于文件的选项，
  则返回不支持操作的规划错误。

说明输出需要保持可解释性：文件、通配、表函数来源的扫描节点
继续沿用现有说明；查询来源直接展示内层计划，无需新增节点类型。

## 5. 执行层改动

执行器中文件与通配分支需要支持列定义头带来的列名：
当规划器透传的列名非空时，输出模式采用透传列名；
文件自带表头的读取逻辑保持不变，但表头行仍按选项决定是否跳过。
通配多文件场景下，首文件确定模式后其余文件只追加数据行，
行为与现有逻辑一致。

表函数分支目前输出列名为按序生成的占位名，
需要改为优先采用透传列名，缺失时回退到占位名。
函数未注册、参数解析失败、执行失败的错误信息保持明确，
不得改为空结果。

查询来源在执行器中不需要新增分支，
因为规划阶段已将其展开为内层计划。
为防止未来有查询种类字符串泄漏到执行器，
需要在执行器入口保留对未知来源种类的明确拒绝分支。

## 6. 测试与验收

解析单测放在加载语句解析器同目录测试模块，
覆盖四种来源、列定义头组合、命名冲突之外的各类错误形态。

端到端用例需要覆盖：文件来源读取、通配多文件合并读取、
表函数来源读取、查询来源读取、带列定义头的列名生效行为、
无头与有头两种形态，以及错误来源的明确报错行为。
查询来源的用例应包含返回子查询与匹配查询两种内层形态。

回归范围包括存在性子查询、合并写入、导入链路、
全文与向量检索，重点确认便捷形态改动未扩散到写入路径。

## 7. 风险与回退

主要风险是括号查询与表函数调用的解析歧义，
通过判定顺序与单测锁定。次要风险是列定义头与文件表头的
优先级混淆，通过列名推导优先级文档与用例锁定。

回退方式为 revert 解析器来源分支与规划器查询分支，
文件与通配行为不受影响。表函数接通本身是纯加法，
回退时仅移除解析产生该变体的能力即可。
