# 同步包剩余任务说明

配套分析见 `sync-responsibility-analysis.md`，本次整改见 `sync-responsibility-remediation.md`。
本文只说明本次未落地、需后续协同的部分。描述使用自然语言，不贴完整代码。

## 口径

投递重试路径已类型化：投递失败载体只看类型化分类与禁用标志，字符串分类入口已删除，
全文投递错误已按永久合法性区分可重试与死信，迟到判定已按类型而非文案区分。
本节之外的内容均视为已完成，不再重复。

## 查询错误分类类型化

现状：同步包管理器的通用错误仍以字符串形式携带全文与向量失败，
查询侧分类函数通过子串判断映射到统一错误种类。
该函数只服务查询与可观测路径，不参与投递重试决策，因此本次未改动。

改法：通用错误改为直接携带类型化全文错误与向量错误，
分类函数只做枚举匹配，不再做字符串包含判断。
构造侧所有经转字符串的位置改为直接透传类型化错误。

验收：同步包内查询分类不再出现子串判断，投递重试行为保持不变。

依赖与风险：涉及同步包公有错误枚举、数据写入入口、查询访问器、
上层接口与服务错误映射，需存储、查询与服务层协同，属于跨包破坏性变更，
不可与投递路径整改混在同一次修改中。

## 远端认证边界类型化

现状：远端 HTTP 认证失败已按状态码归类，远端 gRPC 认证仍在转换边界
匹配稳定的状态码名称，因为传输层目前只透出展示字符串。
该匹配点已收敛到单一转换函数，投递路径不再扩散子串判断。

改法：由远端客户端在错误值中直接携带状态码，
同步包转换函数只匹配状态码，不再匹配展示字符串。

验收：转换边界无字符串包含判断，认证暂停语义保持不变。

依赖与风险：需远端客户端先扩展错误载体，同步包随后跟进，属于跨包变更，
单独成项执行。

## 全文写入范式统一

现状：全文仍保留直接写入与缓冲提交的旧路径，向量走发件箱认领的新路径，
两套一致性语义与读写可见性并存。

改法：只保留发件箱认领路径，删除全文直接写入与事务缓冲旧路径，
调用方一律经发件箱物化、认领、应用、确认。

验收：全文不存在绕开发件箱的写入入口。

依赖与风险：需先迁移全文包测试与上层调用方的旧路径用法，
否则删除会导致编译失败，属于跨包迁移任务。

## 查询与推理能力移出

现状：同步包内仍有查询代理、向量化触发、重排与进度查询能力，
写入路径同步阻塞调用向量化服务，延迟与放大风险高。

改法：同步包只接收已向量化的载荷并负责投递与重建编排，
查询入口收敛到查询层，向量化与重排上移到服务组装层。

验收：同步包不再发起向量化调用，不再承载查询语义。

依赖与风险：需查询层与服务层先提供组装入口与查询收敛点，
属于跨层职责搬移。

## 发件箱与后端继续拆分

现状：持久化发件箱仍聚合持久化、租约、快照、诊断、降级与水位等待，
向量三层边界仍分散在协调器、管理器、后端与重建之间，
全文包测试与开发依赖与同步包的可选依赖构成双向引用。

改法：按职责拆分发件箱的持久化、租约调度、快照诊断等能力，
收敛集合命名、分组、粒度与暂存发布逻辑的归属，
解除全文包与同步包的双向可选依赖。

验收：单向依赖图恢复，拆分后各模块可独立演进。

依赖与风险：涉及存储与迁移层的恢复语义，需联合设计，不在本次执行。

## 明确不做清理的保留项

- 后端策略的人可读名称保留，用于消费者标识前缀与可观测性，不视为遗留。
- 迟到判定与投递失败的可读文案保留，仅用于发件箱持久化、日志与诊断，
  决策分支已全部类型化，不再以文案反推类型。
- 向量过滤新增的条件种类与双向转换已完整配套，不属于本次整改范围，
  无需回退或拆分之外的额外动作。

## 建议顺序

查询错误分类与远端认证边界可各自独立成项，
全文写入范式统一先于查询与推理能力移出，
发件箱与后端拆分最后执行。
各项均需单独的编译验证，不与投递路径整改混合提交。
