# Linkrs 剩余对齐分阶段修改方案

**日期**：2026-11-26（简化版）
**问题来源**：`docs/issue/linkrs-remaining-parity-issues.md` 是剩余问题的单一真相源；本文件只描述修改顺序与验收，不重新定义问题。本版仅保留各阶段改进方向的总述与落地状态；历史中间目标与过程数字不再保留。`group_by_count` 与 `join_two_hop` 的收敛实施见 `docs/plan/group-by-count-join-two-hop-bottleneck-remediation.md`。

## 总则

- 先处理被实测放大的算子缺口，再处理口径、并行放行和深水存储项。
- 所有改动收敛到原模块，不新增替代模块，不做向后兼容包袱。
- 每个阶段独立可回滚：回退该阶段修改的原模块文件即可，不需要数据迁移。
- 正确性优先于速度：快路径只在可证明等价的窄前置下触发，其余形状保持原路径。
- 每个新规则或快路径必须先补反例与空输入用例，再动执行代码。
- 基准结论必须来自安静窗口的重复测量。

## 当前基线

生产默认 `group_by_count` 26–33ms（Ladybug 8.16ms）、`join_two_hop` 约 5.4ms（Ladybug 1.54ms）；`distinct_limit` 约 1.8ms 已反超，`variable_path_count` 大幅领先。剩余成本集中在扫描枚举与可见性、单跳拓扑区间读取、目的端存在性读取、二跳前沿身份解析与度数随机读。生产默认保持 8 workers / 8 partitions、有序并行展开放行、计数前沿不放行。

## 各阶段改进方向总述

- 测量与用例底座：计划标记、资源字段与读写自耗时分段已落地；compare 脚本固化与同规模 expected 回填尚未完成。
- 分组计数与去重：列式分组、行物化切断、typed 局部聚合、局部 TopK、身份直通已落地，秒级瓶颈消除；剩余收敛见新瓶颈文档。
- 两跳连接与变长路径：count-only 折叠与度数合并已落地，变长计数大幅领先；并行前沿默认关闭；剩余收敛见新瓶颈文档。
- 谓词与过滤聚合：批内掩码向量化与 NULL 语义修复已落地；扫描谓词完整替换因 TTL、跨类型与 NULL 语义保持关闭。
- 可观测与资源口径：JSON 与 EXPLAIN 字段已对齐；EXPLAIN 文本的独立阶段展示尚未完成。
- 分区灰度：有序并行展开已在生产默认放行；纯计数链、全局聚合、计数前沿默认关闭。
- 图算法与方言：仅语义锁定，未开始优化；方言用例继续跳过。
- 存储与事务：组提交、检查点保留与 WAL 回收已落地；并行顶点装入、冷检查点第二阶段、批量回放未开始。

## 门槛

- `group_by_count` 生产默认 ≤20ms 且与 Ladybug 倍率 ≤3×。
- `join_two_hop` 生产默认 ≤3ms 且结果恒为 382018。
- 任一数值回归立即停止，先补反例再继续；门槛未达成不通过放宽并行、近似、截断或放宽 buffer 策略换取。

## 不做

近似聚合与采样截断；跨调用可见性或端点存在性缓存；属性内联进 CSR；无证明的存在性跳过；跨机复制、在线迁移与静默截断；多谓词组合下推；去重计数向量化。
