# 第五阶段细化方案：可选评估项

本文是分阶段方案中第五阶段的细化说明，内容覆盖逻辑计划展示、
投影图、共享作用域联合三项。约束保持不变：只修改原有模块，
不新建替代模块；中文写文档，代码与注释保持英文且不引用本文档结构编号。

本阶段只做评估并记录结论，不承诺实现。三项决策均为不实现，
以文档对应关系关闭，未来按需再立项。

## 1. 现状与决策总览

当前查询组合已覆盖管道链式、并集与交差运算、公用表表达式与递归、
存在性子查询与表函数调用，计划展示已覆盖物理计划的表格与图形输出、
实际执行统计叠加。参考项目的三项能力均落在已有能力的边缘，
属于锦上添花而非链路缺口。

决策如下：逻辑计划展示不实现，以现有物理计划展示加优化器备注为准；
投影图不实现，以查询内图算法函数加普通匹配过滤为准；
共享作用域联合不实现，以公用表表达式加并集加管道改写为准。
三项均只需在用户文档中写明对应关系，无需改动解析器、绑定器、
规划器与执行器。

## 2. 评估基准

评估以注册表与执行能力为准，不以参考项目语法存在为准。
参考项目快照中存在语法可解析但函数未注册的断裂，
例如位运算与量词在语法层可接受但在函数注册表中缺失，
绑定阶段直接失败。引用其特性时须先核对可执行性，
不能仅凭语法规则存在就认定为可用能力。

本阶段三项均按该基准核对：不仅看参考项目是否有语法，
还要看其是否有完整的绑定与执行承载；
同样看当前项目是否有可达到同等效果的已验证链路。
若已有链路可改写且语义等价，则不新增语法。

## 3. 逻辑计划展示评估

现状是展示语句支持表格与图形两种格式，支持实际执行统计叠加，
支持性能剖析形态。展示内容来自物理计划转换后的计划描述，
包含算子名称、依赖关系、优化器备注、并行与列存摘要。
内部已存在纯逻辑计划表示与从物理计划剥离物理选择的转换，
但该转换对部分节点类型尚不完备，遇到未覆盖形态会显式报错，
且展示管线始终走物理计划路径，没有逻辑分支。

参考项目的逻辑展示形态是在展示关键字后加逻辑关键字，
直接输出优化前的逻辑算子树。该形态的价值在于调试优化器，
对终端查询语义没有影响。当前项目的物理展示已附带优化器备注、
代价决策与执行统计，对定位性能问题更直接，
逻辑展示的增量信息有限。

若未来立项，改动限定在原有展示链路内：
解析层在展示关键字后识别可选的逻辑关键字，
抽象语法层面在展示结构中增加逻辑标记并透传到绑定结构；
规划层在展示规划器中按标记分叉，逻辑分支调用已有的剥离转换得到逻辑树；
执行层在诊断管线中按标记选择渲染对象，逻辑分支只做纯渲染不实例化执行，
复用已有的表格与图形格式化能力。立项前置条件是先补齐剥离转换的未覆盖节点，
特别是聚合分组键的表达式标识透传，否则逻辑展示会在部分查询上直接报错。

本阶段不满足立项条件，决策为不实现。
文档对应关系为：参考项目的逻辑展示对应当前项目的普通展示输出，
配合优化器备注与执行统计已可满足调优需求。

## 4. 投影图评估

现状是图算法以函数形态提供，包含广度优先、最短路径、
连通分量、页面排名等，查询中可直接调用并配合普通匹配做子图过滤。
没有投影图目录，没有投影图的创建、引用、删除生命周期管理。

参考项目的投影图是一组独立表函数，提供投影图的创建、
基于密码查询的投影、投影图的删除。语义上是在内存中物化一个子图伪库，
后续算法调用针对该伪库执行，避免重复扫描与过滤。
该形态的价值在于同一子图上的重复算法执行可以复用物化结果。

当前项目中同等效果可通过公用表表达式物化一次子图结果，
再多次引用该公用表表达式达到；单次算法执行可直接用匹配加过滤加函数调用表达。
引入投影图目录需要新增有状态的内存对象管理，
包括命名空间、生命周期、失效与并发可见性，
这已超出只修改原有模块的约束，且会引入新的内存与一致性风险。
参考项目中该能力仅见于其中一家，另一家并无对应物，
说明其并非通用刚需。

若未来立项，路径是复用查询内函数调用链路与内存物化链路，
将投影图实现为内存物化视图风格的表函数组合，
不新增替代模块，不引入独立的图目录服务。
立项条件是出现高频重复子图算法且公用表表达式复用已证明不足，
并有明确的内存上限与失效语义需求。本阶段未达到该条件，决策为不实现。
文档对应关系为：参考项目的创建投影图对应当前项目的公用表表达式定义子图；
基于投影的算法调用对应当前项目的匹配过滤加图算法函数调用；
删除投影图对应公用表表达式作用域结束，无需显式清理。

## 5. 共享作用域联合评估

现状是查询内调用语句仅支持函数名加括号参数表加可选产出子句，
调用关键字后直接跟左括号的形态尚未使用。
集合运算支持并集、去重并集、交集、差集，顶层语句支持管道链式，
公用表表达式支持递归，子查询支持存在性、计数、通用子查询与条件内成员判断。

参考项目的共享作用域联合形态是调用关键字后跟括号包裹的外层变量表，
再跟花括号包裹的多个并集分支，分支内可引用外层变量，
整体之后还可接续后续查询。其语义是带关联输入的多分支并集，
公共表达式由各分支共享，避免外层重复展开。

当前项目中多数场景已有等价改写：外层变量先经公用表表达式或管道产出，
再在每个并集分支中引用；非关联的纯并集直接用现有集合运算表达；
递归场景用递归公用表表达式表达；行级展开用拆列语句表达。
新增共享作用域联合的增量仅在于少写一次外层变量声明，
但会引入调用语句的语法歧义、关联变量可见性、分支相关性校验、
多输入共享规划与物化策略等一系列改动。
调用关键字的两种形态在首词元上重叠，解析器需要前瞻区分函数调用与变量表，
绑定器需要为并集分支建立关联作用域并保证与存在性子查询一致，
规划器需要处理共享输入的多分支规划，执行器需要明确物化与流水边界。
风险收益比不高。

若未来立项，改动限定在原有模块内：
解析层在调用语句入口处前瞻识别左括号变量表形态，
命中后解析变量表与花括号内的并集查询并复用已有集合运算结构承载分支；
绑定层将外层变量注册为关联可见变量后逐分支绑定，语义与存在性子查询的关联规则对齐；
规划层复用集合运算规划器的多输入能力，外层输入作为共享侧输入只规划一次；
执行器不新增算子类型，复用已有并集与物化链路。
立项条件是出现大量依赖外层关联的多分支并集且改写后可读性显著下降。
本阶段未达到该条件，决策为不实现。
文档对应关系为：参考项目的共享变量表对应当前项目的前置公用表表达式或管道变量；
花括号内的并集对应当前项目的并集运算；后续查询对应管道接续或外层嵌套。

## 6. 测试与验收

本阶段无实现改动，验收物为本细化文档结论与用户文档中的三种写法对应关系说明。
无需新增解析单测与端到端用例，不占用完整运行次数。

若未来任一项单独立项，遵循解析单测先行、端到端收尾的顺序。
解析单测放在各解析器同目录测试模块，覆盖正常形态、错误形态、命名冲突形态；
规划与执行回归复用现有查询测试与端到端目录，
重点回归集合运算、递归公用表表达式、管道链式、展示管线与图算法函数，
避免便捷形态改动扩散到写入路径。同一立项的用例一次性补齐后统一运行。

## 7. 风险与回退

本阶段不改代码，无回归风险，无需回退。
记录未来立项的主要风险以供立项时直接引用：
逻辑展示的主要风险是剥离转换不完备导致部分查询无法展示，
通过先补齐转换再开放关键字控制；
投影图的主要风险是内存对象生命周期与失效语义不清，
通过内存上限与显式作用域控制；
共享作用域联合的主要风险是关联变量可见性偏差与调用语法歧义，
通过与显式存在性写法的结果对照用例与判定顺序单测控制。
各未来立项均可独立回退，解析层加法回退不影响已有语句。

## 8. 本轮实施完成情况

前四个阶段已按顺序实施并收尾，本阶段复核时基线已完备，
因此本阶段维持评估关闭，不产生代码改动。

第一阶段复核为已达标并做两处收敛：
全文检索四种变体分发可达，合并语句裸集合子句诚实保留，
采样与窗口函数已有解析与规划覆盖；
展示目标中从未被解析器构造的单数与用户角色变体已从枚举与规划分支中移除，
避免规划层存在不可达的误导分支，单数展示与用户角色查询分别走明确报错与独立语句；
标签剥离与标签移除形态维持文档明确标记未实现，不补解析分支。
边合并携带动作子句此前走纯插入路径属于静默丢弃，
现改为规划期显式拒绝，避免写入语义偏差。

第二阶段复核为已实现，无需改动：
命名路径绑定含等号前瞻、路径名注册与重名拒绝、路径函数引用均有覆盖；
过滤条件内联模式经存在性改写复用已有链路，关联可见性与显式写法一致。

第三阶段复核为已实现并做一处修复：
文件、通配、表函数、查询四种来源与列定义头均可达，
查询来源复用内层规划展开，文件专属选项作用于查询来源时显式拒绝，
列名优先级为列定义头优先；
加载选项此前仅接受无关键字括号形态，关键字引导的选项形态无法解析，
现已在原有加载解析入口中兼容该形态；
列定义中的类型名维持仅声明不校验，执行侧统一按字符串读取。

第四阶段复核为实现与评估各守边界：
整属性映射覆盖已端到端实现，判定条件为裸变量加映射字面量，
空映射即清空语义，执行器按替换而非合并写入；
配置设置维持只评估不实现，不新增查询内配置形态，
独立配置更新语句的对应关系以文档为准；
带动作的合并规划出条件选择节点而执行器尚不支持，
维持显式拒绝而非静默退化，裸集合子句修复后同样受该显式约束，
边合并动作子句亦纳入显式拒绝。

本轮查询引擎库测试全部通过，上述收敛改动均在原有模块内完成，
未新增替代模块。本阶段三项维持不实现，验收物仍为本文结论与用户文档对应关系。
