# COUNT 慢查询剩余工作设计

日期：2026-11-16
对应问题：`docs/issue/count-slow-vs-ladybug.md`
状态：部分已完成，本篇覆盖剩余项的设计与本轮实施范围。

## 已完成回顾

上一轮已落地三项修改，均只改原模块，未新增替代模块：

- 边变量计数进入 `count_only` 快路径。优化器识别被计数的变量时不再只认目的槽，边槽同样放行；执行层把聚合改写为对每块边数的求和。`EXPLAIN` 上边计数查询已从 `columnar` 变为 `count_only`，结果数值不变。
- 全局 `COUNT` 向量化。无分组且全部为 `COUNT` 时，按块累加可见行数，不再逐行构造分组键、参数数组和哈希探测；兼容带选择向量（`Filter` 之后）的块。
- 用例期望更新。窄边计数用例的 `EXPLAIN` 断言改为期待 `count_only`。

devs 上 `lsqb-sf0.1` 实测：`KNOWS` 边计数约 52ms 降至约 4ms，`HASCREATOR` 边计数约 1300ms 降至约 175ms，`REPLYOF` 边计数约 1000ms 降至约 160ms，顶点计数基本持平（约 100ms）。

## 剩余差距

- 边计数仍与 Ladybug（亚毫秒）差三个数量级。大头不再是端点解码，而是源端全扫加逐源去重：每个源顶点一个哈希集合，即使单边类型单分区也逐条插入去重，215k 个集合的分配与插入主导了耗时。
- 通用展开路径中，目标端无属性需求时仍走全量顶点解码。需求为空表示只需要存在性，但实现上回退到全属性批量读取，属性解码是主要浪费。
- `COUNT(*)` 的星字面量参数未被快路径识别。解析器把星号解析为字符串字面量参数，快路径只认空参数与身份列，导致 `COUNT(*)` 走逐行求值，尽管其语义恒为计数可见行。
- `est_rows:1` 主要是执行计划解释输出的回退显示。代价决策走的是直接估算调用，真正用于决策的输入并不经过该回退分支，因此它不阻断正确性，只影响排障可读性。
- 并行与分区通道处于禁用状态。打开它需要分区全局聚合的正确性与溢出处理的完整论证，风险高而收益依赖于前几项先落地，不在本轮实施。

## 设计原则

正确性优先于速度，任何改写只在可证明语义不变的窄前置条件下触发，不满足条件时保持原有路径不变，不增加掩盖问题的兜底逻辑。优化只修改原模块，不新增替代模块，不做向后兼容包袱。

## 元数据计数（下一阶段，不在本轮实施）

这是收益最大的方向，单独成阶段的原因是它需要新的执行能力与严格的前置条件论证，不宜与低风险项混在一次变更里。

- 顶点纯计数：单节点模式、单标签、无其他谓词、无可选匹配、无分组去重过滤时，计数等价于该标签在快照下的存活顶点数，可直接调用存储层的标签计数取得，不扫描任何行。
- 边纯计数：单跳、单边类型、出方向、无端点属性与边属性谓词、端点标签与边模式声明的源宿标签一致、无可选匹配、无分组去重过滤时，计数等价于该边类型在快照下的可见边数，可直接调用存储层的边类型计数取得，不扫描源顶点也不组装行。
- 不满足上述任一条时保持现有路径（源扫加度数快路径或列式展开加向量化聚合），同一查询只有一条执行路径，不存在静默降级。
- 正确性要点：快照时间戳与可见性门必须与扫描一致；标签或边类型不存在时返回零而非报错，与空扫描的计数语义对齐；多计数并存时同一计数值复用；空输入仍输出单行零。
- 验收：数值与现有路径逐行比对一致；解释输出可标识元数据计数来源；devs 上顶点计数进入亚毫秒，边计数进入低毫秒。

## 本轮实施的三项改进

### 存在性校验免全量解码

位置在展开列式路径的目标端批量读取。当下游对目标端无任何属性需求时，调用方只需要逐个目标是否存在以过滤悬空边，不需要任何属性值。此时改用空投影的批量读取，存储层跳过属性列解码，只返回存活标记与空属性顶点。需求非空时保持原有投影读取，需要完整实体时保持全量读取，语义不变，只是去掉了纯计数与纯拓扑展开中的属性解码开销。

### 星字面量计数的向量化

全局 `COUNT` 快路径在身份列与空参数之外，再识别单个星字符串字面量参数。解析器对 `COUNT(*)` 生成的正是该形态，其值恒非空，语义等价于计数可见行。满足无分组、全部为计数、每路或为身份列或为空参数或为星字面量的块直接累加可见行数；任一路为可空表达式时整块回退逐行路径。去重与过滤在执行层本就与慢路径一致处理，不引入新的语义差。

### 单表单向度数免哈希集合

存储层按源批量取度数时，先按边类型解析出涉及的边分区。当只涉及单个分区且方向为单向时，每个源的邻边回调恰好与其可见边一一对应，不存在跨分区重复，无需逐源哈希集合去重，改用计数器直接累加。方向为双向或涉及多个分区时保持原有集合去重路径，因为自环与跨分区重复在这些形态下真实存在。调用方已在有存活期列时走物化路径，可见性语义不变。

## 基数显示与并行（明确延期）

- 基数显示回填只影响解释输出的可读性，不影响代价决策的正确输入，延期到元数据计数阶段一并处理，避免触碰计划节点标识重建逻辑。
- 并行分区在全局聚合分区正确性论证完成前保持禁用，当前所有计数改写均为单线程语义正确，多线程下同样正确，不依赖并行开启。

## 验证计划

- 本地一次性运行受影响范围的单测：展开旁路规则、扫描身份规则、阻塞聚合用例、边度数用例。
- devs 上复用已有流程验证：离线编译探针，绑定核执行解释探针，对比五条计数查询的数值与耗时，数值必须与改前一致，边计数耗时显著下降，顶点计数不回归。
- 回滚：三项改动各自独立，还原对应原模块文件即回滚，无需数据迁移。
