# group_by_count / join_two_hop 后继改进设计

现状（batch_acct 轮，v4 库，node1 绑定，三方 16 线程，warmup 1 + run 5 去最大值平均）：group_by 22.01ms（门 20ms），join_two 3.10ms（门 3.0ms）。正确性门全绿，结果逐值一致。两项均差一口气：group_by 差约 2ms 墙钟，join_two 差约 0.1–0.3ms 加稳定余量。

## 1. 剩余成本结构（当前轮计数器）

group_by：扫描工作量约 40ms（枚举解码约 24.5ms、版本可见性约 15.8ms），单跳拓扑读取工作量约 52ms（约 150ns/边，已接近微基准 126ns/边），目的端读取为 0（证明跳过生效），分区偏斜比约 1.2。墙钟约 22ms 主要由扫描与拓扑的并行临界路径决定。

join_two：锚点扫描约 0.3ms，前沿两跳（首跳拓扑 + 尾边度数）在 16 线程下并行墙约 2.8ms，偏斜比约 1.0。串行基线约 5.4ms，并行与证明两项已拿掉约 2.3ms，剩余是前沿本身的工作量。

## 2. 设计方向（按期望收益排序）

### 方向一：顶点存活证明，扫描跳过版本链行走

group_by 扫描的约 15.8ms 花在逐行 MVCC 版本可见性判定（TTL 缺席时已是零成本，见 cursor 的 `row_expired` 快速路径）。若能证明扫描区间内无删除、无并发写入版本，版本链行走可整段跳过，只保留快照时间戳一致性。

落点为存储侧表级只增标记：顶点删除（含孤立顶点删除，当前悬空标记只覆盖有关联边的类型）一律标脏；修复与导入重建标记；查询侧仅在单语句、无 TTL、标记成立时走跳过路径。护栏为无证明不断任何可见性判定，显式事务保持原路径。验证为开/关对照结果逐值一致，扫描工作量下降约 15ms（墙钟约 -1.5ms，八分区并行稀释）。

### 方向二：锚点扫描只读身份列，跳过属性解码

group_by 的 Comment 端扫描只为 expand 提供种子 id，不需要评论属性。若分区扫描未使用身份投影，约 24.5ms 的枚举解码（含逐行记录构造）大部分可省，只读内部 id 与外部 id 映射。

落点为查询侧分区扫描注解：expand 种子需求为纯身份时，扫描下发身份投影，存储 cursor 走无属性解码路径。护栏为投影需求由注解保证，非身份消费保持原路径；语义等价由下发点单测锁定。验证为扫描枚举工作量下降约一半（墙钟约 -1.5ms），结果逐值一致。

方向一与方向二互相独立，任一达成即关闭 group_by 门；两项叠加提供余量。

### 方向三：跨批复用边解析会话（拓扑读取剩余部分）

expand 侧每批重复边类型列表、端点标签、TTL 与证明查询（每批约十次映射查找，112 批约 0.1–0.3ms 墙钟）。落点为 ExpandCtx 持有分区级已解析会话，首批解析、后续批复用；会话记录解析时的时间戳，时间戳变化时回退重解析（无 operation context 的裸读路径保持正确）。护栏为只复用解析结果，不改变读取语义；回退路径保留。验证为拓扑工作量小幅下降，结果一致。期望墙钟约 -0.3ms，主要作为 join_two 余量与 group_by 保险。

### 方向四：join_two 前沿固定开销复核（先测量后定案）

join_two 距门仅一步之遥，当前并行墙约 2.8ms 中固定开销（逐种子闭包、暂存向量、排序、合并）与拓扑读各占多少尚未分离。本方向要求先补前沿分段计数（首跳拓扑、排序、尾边度数、合并四段），再定是融合首跳暂存与尾边累加，还是压缩逐种子分配。护栏为计数先行，无计数不动结构。方向三落地后复测仍超门才进入本方向。

## 3. 门槛与不做

门槛沿用前文：group_by 生产默认不超过 20ms 且对 Ladybug 倍率不超过 3 倍、join_two 不超过 3ms 且结果恒为 382018；任一数值回归立即停止。

不做项：近似聚合与采样截断；跨调用可见性缓存；属性内联进 CSR；无证明的可见性跳过；多谓词组合下推；宽表式反规范化。

## 4. 实施结果（2026-11-27，devs 实测）

- 方向一（存活证明）：重估后收敛。逐行可见性 73ns 中版本链判定仅占约 15ns，其余为必需的外部身份解析输出，完整证明机制的收益上限不足以覆盖其语义面；改为无证明的等价收紧——读 frontier 在 gate 构造时一次捕获（单调性保证判定全等，注释写清），每行省一次原子读。vis 相关单测与全 lib 绿。
- 方向二（身份投影）：证伪为空。扫描 decode 计数器恒为 0，topology_only 身份路径早已生效，无代码可做。
- 方向三（跨批会话）：放弃。tag 解析计数器恒为 0，每批解析约十次映射查找、总计约百分之一毫秒墙钟，不值得新增 trait 面。
- 新增 R1（分片有序归并）：`live_ids_in_slice(_with_vids)` 的全局重排改为分片有序 run 的 k 路归并（编码单调性保证前置），与排序全等（单测锁定）。27K 对微基准归并中位约 507µs、对排序约 597µs，小赚保留。
- 方向四（前沿分段）：已闭环。四段计数入 `FrontierDegrees`、`ColumnarStats`、EXPLAIN 与 bench JSON。分段显示尾边读占主导（3592µs）；顺势落地相邻重复端点去重读数（排序后重复相邻，读一次散射多次，求和语义不变，无额外分配），native 与 portable 组合一致（集成单测锁定）。tail 工作量 3592→443µs（约 -88%）。

生产默认对照：join_two 2.96ms（安静）/ 1.49ms（load 31，工作量结构性下降），门已关闭且有余量，对 Ladybug 约 1×；variable_path 同路径 5.47→1.92ms，结果恒为 400153。group_by 最优 22.01ms，门仍差约 2ms：剩余主因是扫描枚举脚手架与外部身份解析，属下一轮深水区，本轮 R1/R2 只拿走零头。所有正确性门全绿（storage lib 1421、query lib 2364、DQL 324、parallel 27），结果逐值一致。
