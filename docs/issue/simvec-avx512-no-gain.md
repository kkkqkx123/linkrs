# P2 [simvec] avx512 距离核基本无收益（384/768 维反而慢于 avx2）

## 现象（实测）

`simd_vs_naive` 与 `simd_dim_*` 多维度对比（Cosine 为例）：

| dim | naive | avx2 | avx512 | avx512 vs avx2 |
|---:|---:|---:|---:|---:|
| 100k_cosine | 6.9075 ms | 1.8072 ms | 2.3760 ms | **慢 31%** |
| 384 Cosine | 2.0953 ms | 298.26 µs | 349.23 µs | 慢 17% |
| 384 Dot | 1.7690 ms | 236.79 µs | 275.65 µs | 慢 16% |
| 768 Cosine | 4.1879 ms | 728.18 µs | 752.86 µs | 慢 3.4% |
| 768 Dot | 3.8756 ms | 666.59 µs | 673.45 µs | ≈持平 |
| 1536 Cosine | 8.4336 ms | 1.6659 ms | 1.6449 ms | 快 1.3% |
| 1536 Dot | 8.0608 ms | 1.6428 ms | 1.5787 ms | 快 4.0% |

数据来源：`bench_results/linkrs-simvec.log:74-188`

- **avx512 在 384/768 维稳定慢于 avx2**（768 Cosine 753µs vs avx2 728µs；384 维度慢 16–17%）。
- 仅 **1536 维勉强打平**（<5% 收益），且 1536 并非常见 embedding 维度（768/384 更常见）。
- avx2 相对 naive 仍有 3.8–7.0× 稳定收益——即**真正有效的 SIMD 路径是 avx2，不是 avx512**。

## 影响

若运行时默认优先 avx512 路径（或在支持 avx512 的机器上自动选 avx512），最常见维度（384/768）的向量相似度计算**反而变慢**。

## 疑似根因

- avx512 的 512-bit 寄存器在 384/768（非 512 整数倍维度）需 masking / 尾处理，抵消宽度收益；
- avx512 指令通常伴随更低的核心频率（thermal throttle），在中等维度上净收益为负；
- 若 avx512 kernel 未针对维度做对齐特化，masking 开销直接拖累。

## 建议

1. **默认优先 avx2 路径**；avx512 仅在 `dim ≥ 1024 且 512 对齐`时启用。
2. 对 384/768 维移除或特化 avx512 路径，避免回退。
3. 用 CPU feature 探测 + 基准选择（而非盲目优先 avx512），并固化进 CI 回归（dim=384/768/1536 三组对比）。
