# Linkrs 剩余对齐问题清单

**日期**：2026-11-26（简化版）
**状态**：本文件是 Linkrs 与 Neug / Ladybug 对齐剩余任务的单一真相源。本版仅保留问题描述、当前基线与之前改进方向的总述；逐轮实测回填与历史中间数字不再保留。分阶段修改方案见 `docs/plan/linkrs-remaining-parity-implementation-plan.md`，`group_by_count` 与 `join_two_hop` 的瓶颈分析与收敛方案见 `docs/plan/group-by-count-join-two-hop-bottleneck-remediation.md`，两文件不重新定义问题。

## 0. 范围与判定口径

本清单只记录尚未闭环的事项；已闭环事项仅在背景中列出，不再拆分任务。没有测试或基准证据的结论不算完成。

权威证据：`perf-data/parity/results/2026-11-25/resource-aligned/`（三方同机同绑定数据）、`perf-data/parity/results/2026-11-25/ordered-existence-remediation/prod-final/`（Linkrs 最新生产默认数据）。测量口径为 devs 机 node1 绑定、三方 16 线程、warmup 1 + run 5 去最大值平均；Linkrs 64MB buffer 引擎内计时，Ladybug 显式 64MB buffer，Neug 全内存单线程仅作参照。

已闭环的背景事项：COPY 导入约 11 秒量级；九条纯计数三方一致（0.1–0.7ms）；`distinct_limit` 经有序存在性扫描约 1.8ms、反超 Ladybug；`variable_path_count` 大幅领先三方；过滤聚合向量化与扫描谓词 NULL 语义修复；双通道计时、资源字段与读写自耗时分段已接入 JSON 与 EXPLAIN；WAL 回收与检查点保留收敛；typed 分组、局部 TopK、身份主键直通、packed 拓扑直写与结果语义守卫均已落地。

## 2. `group_by_count` 缺口

**问题描述**：单跳出边展开后按目的端主键分组计数取 Top 10，生产默认 26–33ms，为 Ladybug 约 3.2 倍。聚合本身已出局，剩余成本在扫描枚举与可见性复核、单跳拓扑区间读取、目的端存在性读取，分区间耗时极差约 1.6 倍。完成标准为生产默认 ≤20ms 且倍率 ≤3×，结果逐值不变。

**之前改进方向总述**：列式分组计数、行物化切断、拓扑批量读取、内部句柄透传、有序并行展开、typed 分区局部聚合、分区扫描融合与精确局部 TopK、扫描可见性收敛、父端点身份批量解析、拓扑扁平化与目的端 handle 复用、packed 直连局部阻塞算子、身份主键直通。撤回的方向：目的端半连接两版、条件性 CSR 预取、视图排序替代哈希、属性解码批量化，均因无实测收益或回退而未保留。

## 3. `join_two_hop` 缺口

**问题描述**：固定两跳纯计数恒为 382018，当前串行执行约 5.4ms，为 Ladybug 约 3.5 倍。成本主体是中间前沿的外部身份解析与尾边度数随机读。完成标准为生产默认 ≤3ms，结果恒定。

**之前改进方向总述**：两跳折叠为 count-only 前沿、首尾度数读取合并、并行前沿漂移修复（移除共享路由缓存，默认仍关闭）。

## 4. 基准覆盖不足

**问题描述**：三方 parity 仅有 sf0.1 九条纯计数加十一道算子 smoke 用例；LDBC、ClickBench、算法图查询源尚未接入；新增用例无同规模 expected。

**之前改进方向总述**：补 smoke 用例与方言跳过清单、runner 自测（嵌套发现、标记解析、精确/浮点/无序比较、跳过原因解析）、计划标记与资源字段采集。compare 脚本固化与 expected 回填尚未完成。

## 5. 图算法与复杂查询未对齐

**问题描述**：递归片段、双向 BFS、Dijkstra 与 `pagerank` 存在，WCC / SCC / k-core / Louvain 不存在，算法图查询未接入 runner。

**之前改进方向总述**：仅做语义锁定（路径与最短路测试、可执行 smoke），未做优化；近似算法与截断采样明确不做。

## 6. 无方向元数据计数仍未放行

**问题描述**：元数据路径对 `Both` 方向显式拒绝；慢路径公式由单测锁定，是未来放行的唯一 oracle。

**之前改进方向总述**：保持拒绝，仅锁定公式与反例形状；窄前置放行尚未实施。

## 7. 存储持久化与顶点并行装入

**问题描述**：WAL 组提交、批量会话、检查点保留回收已收敛；分片并行顶点装入、冷检查点第二阶段、批量回放未做。

**之前改进方向总述**：持久化下限（组提交、检查点线程池、容量错误）与回收收敛已落地；并行装入需先过四项审计，未过不实施。

## 8. 常驻纪律

新规则或快路径先补反例与空输入用例再合入；改动收敛到原模块，不新增替代模块；正确性优先于速度；基准结论来自安静窗口重复测量。
