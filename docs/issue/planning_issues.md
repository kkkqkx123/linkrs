# 规划器问题清单

范围为 `crates/linkrs-query/src/planning` 及其子目录，含规划入口、语句规划、逻辑与物理节点、物理映射、连接排序与扫描谓词。

## 连接器死代码且连接键为空

连接器模块提供内连接、左连接与交叉连接三个构造器，但生产代码全部使用计划组合器。连接器构造的连接节点携带空哈希键与空探测键，且忽略传入的别名交集参数。唯一引用为优化器引擎测试，生产零引用。空连接键属于正确性隐患，应删除或降级为测试辅助。

## 模板抽取器无人消费

模板抽取器提供读查询通用参数化能力，数据操纵形状归一化提供写语句语义模板能力，计划缓存键提供字符串级归一化能力，三者目标重叠但机制各异。模板抽取器仅在自身测试与模块重导出中出现，流水线编译器与缓存均未引用，属于热路径之外的第三套模板化。数据操纵形状归一化是当前实际使用的写路径模板，与读查询参数化有意分离，应保留。模板抽取器应删除或明确标记废弃。

## 合取项拆分三处重复

扫描谓词模块、连接键抽取模块与冗余标签过滤规则各自实现一套与运算拆分，语义相同但分别操作借用与克隆两种载体。其中两处为逐行相同的借用版本重复，另一处为克隆版本。另有连接键的变量归属判定与扫描谓词的单列提取属于同一表达式行走逻辑的两种方言。应收敛到扫描谓词作为唯一来源。

## 索引选择与代价模型多套并存

扫描搜索策略目录、通用索引扫描规划器与复合索引分析器各自持有索引信息适配与代价判断，分别服务匹配路径、通用入口与查找语句。连接排序目录的动态规划枚举与代价模型是第四套代价决策。索引信息与代价模型配置类型未统一，复合分析器与搜索策略的适用范围仅靠注释区分，新人容易误调。

## 语句与子句规划器双份实现

返回、产出、解包、公共表表达式等同时存在独立语句版本与子句版本，文档注明为有意双份，分别服务独立语句与匹配管道复用。但解包等规划器的物理出口不统一，有的直接调用物理映射，有的经由逻辑根统一封装，绕过了统一的物理提示收集流程。

## 递归规划两级分发

规划枚举提供统一的已决议语句路由表，管道与集合操作等递归规划器内部再做一次子语句匹配并递归调用规划入口。子语句新增变体时两处都要修改，路由表形同虚设的部分场景存在遗漏风险。

## 逻辑物理双树不对称

正向逻辑到物理转换为全量覆盖，反向物理到逻辑为按需部分桥接，管理、算法与搜索算子故意缺失并降级为扁平执行。物理独占算子约二十余个，逻辑侧无对应镜像。聚合等算子在反向桥接中存在信息丢失，需要调用方额外携带上下文表达式。双树现状可用但增加了心智负担，收敛为单树属于远期结构性工作。
