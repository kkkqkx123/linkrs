# Issue：Linkrs 与 Neug / Ladybug 对比：剩余差距与改进方向

**日期**: 2026-11-17
**发现来源**: `docs/archive/perf/parity/2026-11-12-lsqb-sf0.1.md`、`docs/plan/constant-true-filter-root-cause.md`、`docs/plan/count-next-stage.md`、`docs/plan/count-followup-analysis.md`
**状态**: 分析与后续方向；2026-11-17 已按提交 1a5f78d6 及后续三轮专项更新进度，剩余任务细化方案见 `docs/plan/linkrs-parity-remaining-plan.md`

## 0. 范围

基于 `graphdb-ben` 三方基准（LSQB-sf0.1）与现有计数优化阶段，对照 Neug / Ladybug，
列出 Linkrs 仍未对齐的差距与改进方向。本文只记录方向，不包含完整代码。

## 1. 已对齐的能力（本轮 count 阶段之后）

- LSQB-sf0.1 九条 COUNT 三方整数一致（1700 / 215488 / 172438 / 18135 / 215488 / 172438 / 107461 / 108027 / 172438）。
- 纯 count 执行时间从秒级降至亚毫秒（q1–q9 median 0.13–0.60 ms），与 Ladybug 亚毫秒级对齐。
- 计划形状：`Filter(true)` 从纯计数链消除；rowless scan + identity 注解生效；元数据计数路径覆盖纯计数。2026-11-16 曾因行缺失重建与根输出整实体问题回滚恒真消除（见 `docs/plan/count-followup-analysis.md`），2026-11-17 已随行缺失感知与根输出审计重新安全落地（见第 3 节）。
- 解释输出：compiling/executing 拆分、分片标记、回退原因字段可查。

## 2. 剩余差距（按影响排序）

### A. 导入 / COPY 性能（差距最大）

- Linkrs sf0.1 导入最慢单边 29.5s，Ladybug 3.75s，Neug 7.95s（约 8–10×）。
- 原因：每条 COPY 单独会话/进程开销、WAL fsync、checkpoint、表头 sidecar 改写；无批量导入。
- 改进方向：`begin_bulk_load` 会话、批量提交、延迟 checkpoint、WAL 批量 fsync、并行表导入；参考 Ladybug `serializer.py` 单进程多语句模式。

### B. 算子微基准未对齐

- Ladybug 主套件 54 条 query（过滤/Join/聚合/递归/最短路/图算法）+ ClickBench 43 条；Linkrs parity 仅 LSQB 9 条 count。
- 改进方向：按 parity 文档实施顺序落地 LDBC-sf10/sf100 算子组、ClickBench schema 映射、算法图（PR/WCC/shortest path）；建立 skip.txt。

### C. 编译 / 执行拆分与可观测性

- parity bench run 目前仅 wall-clock `Instant`，Ladybug 报告 compiling/executing 分离；优化器规则批与 CBO 编译开销可能显著。
- 改进方向：run 模式接入 `QueryResult` compiling/executing 时间；EXPLAIN 输出阶段耗时；对齐 Ladybug 口径。

### D. 并行度利用不足

- 分区总开关默认关闭；neug AP 单线程；Ladybug 用 `sched_getaffinity` + 90% 内存。
- 改进方向：按形状灰度放行分区（先纯计数链，再全局聚合）；利用 cgroup 内存限额；内核升级后启用 io_uring。

### E. 内存模型与效率

- Linkrs 无 `--bm-size`，RSS 峰值不可控；列式/typed layout 内存占用；Ladybug buffer manager 90%。
- 改进方向：暴露 buffer pool 大小配置；在 explain 中报告 RSS 峰值与库体积。

### F. 图算法与复杂查询

- 递归、最短路、WCC/PR 未对齐；Linkrs 递归片段算子存在但未基准。
- 改进方向：纳入算法图基准；优化递归 fixpoint 的物化与并发。

### G. 存活期 / TTL 与无方向计数

- 元数据计数对 TTL 标签拒绝（正确但慢）；无方向边计数元数据未支持；中间层（只解码 TTL 列）未实现。
- 改进方向：落地游标单列批量计数与边计数静止/提交计数；无方向计数按公式（出腿 + 入腿 − 自环）支持。

### H. 谓词 / 分组计数向量化缺口

- 带谓词全局计数、分组计数批量路径不完整；去重计数保持慢路径。
- 改进方向：补齐过滤条件下推到扫描谓词的形状；分组可空参数空值语义锁定；去重计数保持慢路径（正确性优先）。

### I. Embedded 调用侧绑定

- 纯读语句可能仍走写能力绑定（门限已放行但绑定未改）。
- 改进方向：embedded 自动提交单语句路径按语句分类选择绑定，纯读走只读入口。

### J. 存储与事务层

- io_uring 不可用（内核 4.15）；WAL/checkpoint；并发写入；CapacityExceeded 处理。
- 改进方向：内核升级；批量 WAL；checkpoint 并行化（已有 cold-checkpoint 设计）。

### K. 优化器复杂度

- 单遍 fast shape chain；规则数量多；cross-batch oscillation 风险。
- 改进方向：保持单遍但收紧前置；规则注册按形状裁剪；不新增替代模块（按架构规则）。

## 3. 现有进度（2026-11-17，提交 1a5f78d6）

提交主题为查找下沉与聚合审计修复、内嵌子句与聚合过滤修复，共改动 57 个文件，约 2300 行新增。
本节只记录与本文差距项的对应关系，不复述完整代码。

### 已闭环：恒真过滤消除重新安全落地

- 对应 `docs/plan/count-followup-analysis.md` 第一节记录的回滚事项：字面量真过滤擦除曾因放行无操作投影消除与限制下沉，导致行缺失扫描失去行重建器，`RETURN n LIMIT` 类查询从 3 行变 0 行。
- 本轮在同一条消除规则上恢复真值分支，仅接受无子查询的字面量真条件；同时补齐两个正确性护栏：行缺失扫描的直接无操作投影不再消除，根输出经透明保持器直达客户端的裸实体变量不再置身份注解。
- 效果是纯计数链与简单扫描链的常量真残留可集中消除，且不再破坏行视图重建与裸实体装箱契约。原回滚结论被本轮取代，根治方向中的这两项已落地。

### 已闭环：聚合过滤与分组子句端到端打通

- 解析器补齐 `COUNT(*)` 带过滤后缀形态，绑定器为聚合调用新增逐聚合过滤谓词，为分组语句新增分组后过滤条件，为投影子句新增行过滤条件。
- 规划器把过滤谓词带入聚合节点，把分组后过滤 lowering 为聚合之上的过滤节点，独立分组规划器把过滤引用列并入输入投影，返回子句规划器把过滤引用列并入预聚合投影。
- 执行层为聚合与部分聚合新增逐聚合过滤向量，任一聚合带过滤即关闭行计数快捷路径与批量表达式路径，逐行裁决后再累加，分组本身不受影响而对应聚合跳过累加。
- 分组类型显式收敛：非标准分组类型在绑定期直接报错，不再进入规划与执行。
- 对应差距 H 的正确性部分：带过滤聚合不再静默丢过滤条件；向量化仍只覆盖无过滤形态，带过滤形态按设计走慢路径，见剩余方案。

### 已闭环：内嵌产出子句尾部统一

- 新增共享的逻辑与物理尾部 lowering，顺序固定为行过滤、去重、排序、采样、分页，分页采用单限制节点编码。
- 查找、过滤顶点、过滤边、子图、路径、前往语句统一复用该尾部；查找语句的存储层行上限不再预填，改由显式限制节点承载并交由限制下沉优化决定是否折叠；查找仅允许出现在管道首阶段，非首阶段的查找在绑定期直接报错。
- 对应差距 B 的算子覆盖基础：各语句的去重、排序、分页语义在逻辑与物理两棵树上对齐，为后续按 Ladybug 主套件补算子组扫清前置分歧。

### 已加固：身份注解审计

- 顶点与边身份注解同时新增根输出裸实体检查：根输出仍携带扫描变量且自扫描向上全链保持裸列时，即使每步孤立看无害，也禁止置身份标识，保证裸实体返回仍走装箱值。
- 非根同名透传投影视为透明，改名透传仍阻断；分组集合引用扫描变量阻断；聚合逐函数过滤按实体安全规则审计；半连接残留非等值条件纳入审计。
- 对应差距 G 与 H 的正确性基础：纯计数与分组链的行缺失与身份快路径不再因审计漏判而错装箱。

### 部分进展：限制下沉与采样语义

- 限制下沉在真过滤消除恢复后仍受行缺失护栏约束，采样在查找尾部中为显式规划错误。语义收敛完成，但限制折叠率与采样支持仍是开放项，见剩余方案。

### 本轮未触及（仍为剩余任务）

- 导入批量优化、编译与执行拆分、分区灰度放行、内存模型与资源上限、图算法基准、无方向元数据计数、存活期单列中间层、谓词与分组向量化深水区、内嵌调用侧只读绑定、存储层批量持久化。
- 其中内嵌纯读绑定与游标存活期过滤在 `docs/plan/count-followup-analysis.md` 中记为已落地，本轮改动未覆盖这两条路径，剩余方案按先复核现状再决定是否重做处理。
- 存储边计数文件本轮只有格式化改动，无功能变化。

## 4. 改进优先级建议

- P0（正确性/性能快赢）：分区灰度放行、边计数静止快路径、TTL 中间层、顶点表安装专项（分析先行）。
- P1（对齐 Ladybug）：LDBC-sf10 算子组、ClickBench、编译/执行拆分、RSS/库体积报告。
- P2（深度优化）：图算法基准、io_uring、内存模型、谓词/分组向量化。

## 5. 验证方式

- 使用 graphdb-ben 三方 runner（Linkrs/Neug/Ladybug）在 devs 上跑 sf0.1/sf1/sf10，记录 median_ms + status + rows match。
- 结果落盘 `perf-data/`（已 gitignore），趋势记录而非硬性门。
