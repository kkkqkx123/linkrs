# 边表方向 1-3 细化修改方案

> 对应对比分析第 9 节前三条，按 1→2→3 顺序实施，每阶段独立可验证。
> 本文档只描述目标、改动点与验收标准，不贴完整代码。

## 阶段一：列级脏跟踪下沉到组级（增量 checkpoint）

现状：属性列脏以全局 `dirty_columns` 记录，组级只有布尔 `column_updated` 痕迹。
增量补丁用全局脏列集合为每个脏组打补丁，出现跨组过量重写与重编码；
`refresh_column_stats` 同样按全局集合刷新。

目标：补丁与统计的作用域跟随组，干净组文件不动，脏组内干净列复用上次落盘字节。

改动点：

- 在 `EdgeStore` 新增按 owner 组记录脏列名的映射，写时按边 owner 落组。
- 属性点写路径在解析出列名后同时记录组级脏列；拓扑插入与删除保持只记组痕迹，走全量重写分支。
- 落盘时每组用本组脏列集合决定增量补丁范围，无组级记录时回退到全局集合保正确。
- 落盘后按组清除已刷新的组级记录；schema 加列、删列、改名同步维护组级记录中的列名。
- 加载、形态发布、重映射等重建路径清空组级记录，与现有脏标记清理保持同序。

验收：纯属性点写只重写脏 owner 组文件；多组各写不同列时每组补丁范围限于本组列；
无痕迹回退路径计数器行为不变；既有增量 checkpoint 测试全过。

## 阶段二：收敛 Bundled 与 Columnar 能力断层

现状：Bundled 准入条件在建表选择器与迁移预检两处重复书写；
`Auto` 选中 Bundled 时只记 info 日志，操作者不易察觉其 freeze、rank、
MVCC、在线改列限制；指引文本未覆盖 rank 与 MVCC 限制。

目标：准入条件单源化，`Auto` 选中 Bundled 时给出显性操作提示，
指引文本补齐全部限制，不改变任何准入语义。

改动点：

- 在 `edge` 模块新增 Bundled 资格判断与原因说明，供建表与迁移两处共用。
- 建表 `Auto` 解析改调该判断；选中 Bundled 时输出警告日志说明限制与强制 Columnar 的方式。
- 迁移预检改调该判断，保持原有错误文本不变。
- 记录形态指引文本补齐无 rank、无 MVCC、单边策略限制。

验收：原有形态选择与迁移测试全过；资格判断单测覆盖零属性、
单可编码标量、多属性、不可编码类型、单边策略五种情形。

## 阶段三：降低权威与属性二次查表读放大

现状：可见性判定存在系统性重复。邻接投影、点查、带门扫描、
迭代器 `next` 均为外层拓扑先判一次，投影入口再判一次；
带门路径外层用门判定、内层用非门复查，存在语义错配；
Bundled 无行地址读对每条边全表扫描定行，批量过滤退化为平方复杂度。

目标：一次判定多次复用，门语义内外一致，Bundled 批量过滤利用已有行地址。

改动点：

- 新增可见性已判定前提的投影与记录组装入口，内部不再复查权威。
- 外层已判定的邻接投影、点查、带门扫描改调已判定入口；
  带门路径借此消除内外门语义错配。
- 新增已判定前提的谓词匹配入口；迭代器 `next` 改为判定一次，
  后续谓词与投影全部复用该结论。
- Bundled 无行地址读拆分为已判定变体；批量过滤在已有行地址时直接按行解码，
  不再逐边全表扫描。

验收：所有读路径返回结果与改前一致；可见边权威查询次数降至每边一次；
Bundled 批量过滤不再含逐边全表扫描；既有读、投影、谓词、迭代器测试全过。
