# 编译服务器编译环境配置与操作规范

## 1. 结论先行

编译服务器（`ssh devs`）已具备直接以 release 模式编译本仓库的条件，且**全程不需要 sudo 权限**。本次任务未使用所提供的 sudo 密码，未在任何命令、文件、历史记录中留下密码明文，也未新建或修改任何免密配置，无残留。

现状摘要：远端已有 Rust stable 1.99.1 工具链（用户态安装），系统编译依赖齐备，仓库源码已同步至 `/data/kkkqkx/linkrs/repo`。SSH 密钥登录本来就可用，未做任何改动。

## 2. 权限与密码处理规范

### 2.1 SSH 登录

`~/.ssh/devs` 密钥登录可用，已用批处理模式验证通过。未向服务器写入任何新的公钥，未改动 sshd 配置，不存在 SSH 侧残留。日常操作保持现状即可，禁止为图方便改用密码登录。

### 2.2 sudo 密码

本次环境配置与编译构建均在用户态完成，不需要 sudo，因此所提供的 sudo 密码一次也没有被使用。具体做到以下三点：

- 命令中不出现密码明文，不使用管道传递密码、不把密码写进脚本或临时文件。
- 不为使用密码而设 askpass 等变通手段，因为根本用不到。
- 不设置任何 NOPASSWD 规则，不存在需要移除的配置。

### 2.3 将来万一需要 sudo 的规范

以下操作才需要管理员或 sudo：apt 安装系统包、调整频率策略、划分 cpuset、安装 perf。若将来确需执行，遵守：密码只在独立交互终端手工输入，绝不进命令字符串与脚本；如需临时 NOPASSWD 以支撑批量操作，提前声明范围与时限，任务结束后立即回滚 visudo 修改，并用无密码试探与历史记录检查确认恢复原状，不留临时文件。

## 3. 工具链与系统依赖现状

远端 `~/.cargo/bin` 已有 rustup 管理的 stable 工具链，版本 1.99.1。注意非登录 shell 的 PATH 不含该目录，每次执行前需先将其加入 PATH。本地工具链为 1.98.0，版本略有差异；由于产物统一在服务器上构建，本地版本只影响代码编写，不影响基准产物，但每次构建须把远端实际版本记入结果。

系统依赖经核查全部就绪：gcc、make、pkg-config、cmake、clang、python3、git，以及 OpenSSL 开发头。protoc 缺失，但默认特性构建不需要它，只有显式开启 grpc 特性时才需要；届时优先采用用户态方案（下载官方预编译 protoc 放个人目录并加入 PATH），避免为装一个二进制动用 sudo。

远端网络可访问 crates 源，首编可正常下载依赖。构建目标目录默认落在源码树下的 `target/`，位于 `/data` 大分区，不会挤占根分区。

## 4. 源码同步规范

以打包压缩后复制为准，不直接同步工作区。打包排除项固定为：所有 `target` 目录、前端目录、顶层 `.git`、日志目录与日志文件、各类 node_modules。顶层 `.git` 体积大且构建不需要，随包附带一份构建信息清单即可，内容为提交哈希、打包时间、本地工具链版本与打包时的工作区状态。

产物命名按提交短哈希区分，解压到版本无关的固定目录，清单文件一并放入。解压后必须验证排除项确实不存在，再开始构建。日常小改动可用增量同步代替整包，但排除规则保持一致，且同步前先在远端确认无构建进程正在运行。

本次同步：31MB 压缩包对应 170MB 源码，提交为 2c9b92f8，已验证远端无 target 与前端目录。

## 5. 编译执行规范

统一在服务器上执行 release 构建，构建参数保持仓库基线，不私自加 RUSTFLAGS 特化。基准对比用的特化版本另行单独立项，不混入默认口径。

为与基准测试互不干扰，编译限定在 NUMA node0 的核上运行，并限制并行任务数，node1 始终预留给基准。构建必须以后台方式运行，全部输出先落盘到版本化的构建日志，严禁边编边刷屏查看；需要检查时只读日志尾部。构建产物、日志、构建信息清单三者同版本存放，可追溯。

## 6. 资源使用礼仪

编译与基准互斥，同一时段只做一件事。启动前检查系统负载与在线用户，负载异常或他人任务在跑时先等待。编译期间保持核亲和性，不抢占预留核。构建完成后归档日志，远端保留原始记录，本地只回传结论。
