# 下一阶段改进效果分析（有代码改动，编译服务器复测）

本轮按设计文档实施了四项改动，全部收敛在原模块，
默认语义不变。远端原始日志：
`/data/kkkqkx/linkrs/results/stage2-code/`（正确性门）、
`/data/kkkqkx/linkrs/results/stage2-quiet/` 与
`/data/kkkqkx/linkrs/results/stage2-final/`（效果数）。
此前那份无改动的复测记录作废，以本文为准。

## 改动清单

快路径单链遍：链遍预算由常量改为实例可配（默认三遍不变），
快路径在构造时置为单遍。共享实例复用：
统计视图与代价实例在快路径入口构造一次并在各阶段间共享，
全量路径调用点改为显式传入等价实例，行为不变。
重放分段计时：恢复统计新增解析、过滤、恢复、应用四段耗时，
打开路径落盘透出，崩溃基准一次性报告打印分段。
分区决策透出：分区成功时把决策原因写入诊断注记，
此前只走调试日志，解释输出中不可见。

## 正确性门

服务端检查通过。查询库全量单测通过（新增边扫描等价、
单遍遍数锁定、分区注记三项，另有一项预先存在的
缺文档失败，与本次改动无关）。
pipeline、dql、dml、语料等价、统计收集器、缓存探针
等集成套件全绿。存储库一千三百九十三项通过，
两项重启失败见下节（潜伏回归，非本轮引入）。

## 冷规划效果（画像分段口径）

冷点查快启发式阶段：改动前约二百八十一与三百四十三微秒，
改动后八个样本分布在一百七十六到二百二十九微秒，
中位约一百九十五微秒，下降约一百一十五微秒（约百分之三十七）。
机制证据与计时一致：门控形状下第二遍链遍的五个分批
零规则命中，纯属校验开销，单遍恰好砍掉这部分。
代价侧共享实例无可分辨效果（代价侧阶段前后均为四十余微秒），
构造本就廉价，保留为卫生性简化。
其余阶段（移除因子化、因子化、行估计）在噪声内不变。
合数因三十次均值中热路径占二十九份，无法分辨冷侧百微秒量级变化，
不作为验收口径，与设计文档的口径一致。

## 重放分段效果（首次分段数）

两千顶点四千边下，带尾部日志 reopen 一次性墙钟约一千八百八十毫秒，
干净基线约一百二十七毫秒。分段显示尾部重放三千条目中
解析约三毫秒、过滤与恢复为零、应用约十五毫秒。
应用侧不是缺口驱动项，设计文档中批量应用侧的前提被证伪，
批量化延期。剩余约一千七百五十毫秒落在恢复管理器之外的
收尾段（延迟边排空与恢复末全量检查点在机械盘上的落盘），
下一步先给收尾段加同口径分段计时，再决定动向。

## 并行效果

分区决策注记已由新增单测锁定在真实分区计划上，
集成套件确认解释输出无回归。封顶机制本身本轮未动，
干净窗口前后测仍按设计文档执行。

## 潜伏回归上报（另立项，不在本轮修复）

存储库两项重启测试确定性失败：
创建并修改标签与边类型后重启，
以及创建后清空间后重启，均报检查点持有未知边分区。
错误串诞生于边持久化改动提交，终验只跑了分组窗口子集故未暴露，
本轮全量跑出。根因方向是检查点恢复跑在模式日志重放之前，
而新逻辑把缺分区从静默跳过改为硬错误。
本轮改动在该路径上只有计时与日志格式，不可能引发，
证据是失败栈只涉及未改动文件。修复需动引导顺序，
超出本阶段范围，单独立项。
