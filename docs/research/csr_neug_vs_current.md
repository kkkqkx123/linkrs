# CSR 变体对比研究：ref/neug 与当前项目

> 范围：只对比“边邻接 CSR 变体”子系统，不含查询、事务、列存属性等外层。
> 源码依据：`ref/neug/include/neug/storages/csr/`（`csr_base.h`、`immutable_csr.h`、
> `mutable_csr.h`、`nbr.h`、`generic_view.h`）与 `ref/neug/src/storages/csr/`
> （`immutable_csr.cc`、`mutable_csr.cc`）；当前项目 `crates/graphdb-storage/src/edge/`
> （`csr_variant.rs`、`csr_trait.rs`、`csr_shared.rs`、`mutable_csr.rs`、
> `single_mutable_csr.rs`、`pure_csr.rs`、`bundled_csr.rs`、`immutable_csr.rs`、
> `edge_table/checkpoint/snapshot.rs`、`node_group/freeze.rs`、`immutable_csr/pack.rs`）。
> 本文档使用中文，代码标识保持英文原文。只收录对比研究结论，不收录针对当前项目的修改建议
> （修改建议见 `docs/plan/csr_neug_followup_plan.md`）。以代码为准。

## 1. 一览对比

| 维度 | ref/neug | 当前项目 |
|---|---|---|
| 变体划分 | `CsrType` 五态：`Immutable / SingleImmutable / Mutable / SingleMutable / Empty`，全部是 `EDATA_T` 模板具现 | `CsrVariant` 七态：`Multiple / Single / Pure / Bundled / Frozen / Mapped / None`，枚举加宏分发，无泛型膨胀 |
| 选型输入 | 边策略 `EdgeStrategy{kNone, kSingle, kMultiple}` 定每个方向的 CSR 类别 | 两级选择：`RecordForm{Pure, Bundled, Columnar}` 定记录形态，再由 `EdgeStrategy` 定列式形态下策略；冻结与映射是正交运行态 |
| 槽位内容 | 邻居加边数据：`ImmutableNbr{neighbor, data}`、`MutableNbr{neighbor, timestamp, data}`，`EmptyType` 特化省数据区 | 拓扑加版本投影：热端 `HotNbr{endpoint, rank, edge_id}`、冷端 `ColdStamps{delete_ts}`，行内无属性、无创建戳 |
| 边身份 | 源顶点加行内偏移，或源加目的扫描；无全局边号 | 全局 `EdgeId` 为主键；偏移与位置只做带重验的快路径 |
| 重边表达 | 重复邻居条目，无显式键 | 显式 `rank` 列；纯拓扑与内联形态强制 rank 为零 |
| 并发 | 逐顶点自旋锁数组，单条写加行锁，时间戳与边数用原子量 | 零锁，单写者由借用检查器保证；多核扩展靠分片组级并行 |
| 增长 | 逐行独立重分配（1.5 倍扩容），批量全量重建（保留系数） | 主块加分级溢出：首边前零度行不分配，溢出只追加不拷贝旧块，宽行有 live 索引 |
| 可见性 | 时间戳内联条目，迭代器按读时间戳过滤；不可变系恒可见 | 行内只存删除戳投影，可见性走外部版本权威按边号判定 |
| 读形态 | 零拷贝 `GenericView` 值对象经 `get_edges` 得 `NbrList` 区间遍历；有序前缀可二分 | 借用回调、调用方缓冲、分配式三种形状；冻结与映射行恒有序可二分，其余行走插入序 |
| 属性 | 模板参数内联或经访问器跳外部列；导出重建只适用于可变系 | 默认拓扑零属性，属性在独立列存中按边号索引；只有单标量走内联值列 |
| 删除 | 按偏移写墓碑或哨兵，原地压缩，回滚恢复；无写写冲突错误码 | 按边号删除，异时间戳重删报写写冲突，同时间戳幂等；位置删除带期望边号重验 |
| 持久化 | 内存映射容器即主存储，多文件落盘，指针数组内存重建，打开校验边数 | 堆内字节流转储加尾部校验与边数重算；只有冻结服务 sidecar 用只读映射且可丢弃重建 |

## 2. 变体覆盖关系

`ref/neug` 五态在当前七态中的下落：可变多边对通用多边（同名不同实），
可变单槽对单槽（布局重做为分段稀疏加存在位图），不可变对冻结（打包只读，
无容量数组、无溢出链、无锁），单不可变被冻结吸收（经专用打包器打包，不再保留专用变体），
空类被空占位吸收（只记顶点容量）。新增的三态对应 `ref/neug` 用模板特化与内存级别覆盖的场景：
纯拓扑（12 字节每边，无 rank、无时间戳）、内联单值（20 字节每边，恰好一个可编码标量）、
映射服务视图（与冻结同逻辑的只读内存映射）。

## 3. 机制对应关系

经核验，下述 `ref/neug` 机制在当前项目中都有已落地且通常更细的对应物：

- 全局未排序水位加有序前缀二分：对应逐行内存有序标志加阈值扫描路由，粒度更细。
- 批量保留系数重建：对应批量预留路径，另有分片组级并行。
- 仅可变系可用的导出重建：对应按形态直达打包器，覆盖单槽、纯拓扑、内联标量三种冻结源，
  不经临时通用表，不伪造时间戳。
- 打开时度数之和与边数一致性校验：对应加载时尾部校验加边数重算，失败拒绝。
- 行锁点写并发：对应分片组级并行，是不同的扩展轴。
- 大页内存级别：对应快照映射打开时的大页建议，堆内不做大页主存。
- 单条写逐行扩容：对应主块空位填充加水位门控墓碑复用加溢出追加。

## 4. 结构性差异

其余差异属于设计分歧而非能力缺口：模板具现对枚举分发、行内属性对拓扑与列存分离、
行内时间戳对外部版本权威、映射直写主存对堆内转储加派生只读缓存。
这些分歧各自成体系，单点借鉴不能移植。

## 5. 待后续分析参考的开放点

- 高度数行的主块空位加溢出链指针追逐，是当前布局下唯一经对比仍无对应优化的行扫描成本。
- 冻结单行回收仍是整表量级操作，与其余形态的逐行回收不对等。
- 只读形态下计数型删除返零、结果型删除报错的双风格是已记录的有意契约，
  调用方需按类型统一处理，不再逐入口记忆。
- 映射清空回退为空占位的类型跃迁由组层显式承接，后续分支按当前判别式调度。
