# 边表已否决与已保留的优化方向决策记录

本文登记边表治理中评估后主动放弃（或主动保留原状）的四个方向，逐项给出背景、已做工作、否决原因、决策与重启条件。后续对比或再议任何一项前先读对应小节，不可在没有本文参考的情况下重新尝试。

---

## 1. 跨调用可见性投影缓存：否决

**背景**。边表读路径每次可见性判定与属性投影都要经过权威（`MVCCManager`）与属性映射（`CsrWithProperties`）的查表。曾考虑引入跨调用的行级可见性投影缓存：一次判定，多次复用，把点查的定位加判定压缩为纯缓存命中。

**已做工作**。以下复用全部只在单次调用内生效，不跨调用持有结论：批量可见性判定（`are_visible`）、批量保留可见行（`retain_visible`）、谓词匹配的已判定复用（`matches_pushdown_assume_visible`）、扫描迭代器每条目单次权威判定后复用于谓词与投影、表层点查一次定位加复用解码（`merged_get_edge` 系列加 `assume_visible` 投影）、上下文层点查融合（一次定位同时返回记录与边标识，单次加锁完成复核）。

**否决原因**。可见性权威只能有一处。跨调用缓存是第二个真相来源，其失效边界必须覆盖每一条提交路径：暂存提交、分组直写、记录形态切换、预写日志重放、回收复用、检查点加载。漏掉任何一条即提供过期读，且过期读无声无息，不同于 fail-closed 的显式错误。缓存的收益是省一次映射查表，风险是破坏可靠性底线，不符合正确性优先于性能的顺序。

**决策**。不做跨调用缓存。读放大只通过单次调用内复用治理。

**重启条件**。同时满足以下两条方可重议：其一，生产画像证明权威查表占点查延迟的主导份额；其二，拿出带中心化失效的设计（例如权威版本号纪元，任何提交推进纪元，缓存项绑定纪元比对），并证明全部六条提交路径都推进纪元。缺任何一条维持否决。

## 2. 内联形态去留：双形态保留

**背景**。边表记录形态三分：无属性的 `Pure`、单标量内联的 `Bundled`、全功能列存的 `Columnar`。`Bundled` 带硬性限制：无 rank、无多版本链、带有效值不可冻结、不支持在线结构变更，超限必须迁回 `Columnar`。曾考虑拆除内联形态，用单列列式统一替代，减少形态分叉。

**已做工作**。短期收敛已完成：准入规则集中在 `is_bundled_eligible` 一处并与迁移预检共用，建表自动选中内联时明确告警并指引可演进 schema 强制列式，冻结可行性给出迁移指引，内联表拒绝在线结构变更并指引重建，离线与在线双路径形态迁移可用且切换前预写日志被隔离。

**否决拆除的原因**。拆除的收益是代码分叉减少，代价是全部单标量表被迫走宽行加属性映射，读写各多一次跳表。没有任何基准证明单列列式的差距在噪声范围内，也没有任何故障归因到形态分叉。拆除还是全表数据迁移，风险远大于未经证实的收益。定位调整为：内联是单标量表的快路径，列式是可演进形态的默认选择，自动推导加显式迁移是唯一的收敛机制。

**决策**。双形态保留，不拆除内联。

**重启条件**。满足任一条方可重议：其一，对比基准证明单列列式在读写延迟与空间上与内联的差距在噪声范围内；其二，形态相关分支被证实为故障或维护负担的主因。重议前先跑基准，重议后先给迁移窗口，不可直接删除。

## 3. 边写并发化：否决

**背景**。边表单次提交含多段固定成本：预写日志落盘、拓扑预留、双腿写入、索引与 owner 维护。曾考虑引入顶点级锁或分片级并行写来降低点写延迟。

**基准证据**。`edge_point_write_bench`（1000 边，中位数，3 次重复）：单条内存 19.25 微秒每边，单条持久 19.98 微秒每边，批量内存 4.11 微秒每边，批量持久 4.85 微秒每边。批量约为单条的四到五倍便宜，持久与内存单条差距仅约百分之四。按基准自带的决策门限（落盘占比超六成方可视为 durability-bound），当前未触线：延迟主要来自单次提交的固定成本，而非落盘。

**否决原因**。边表按单写者纪律设计，`switch_record_form_online` 等操作依赖 `&mut self` 串行一切写入。引入并行写要重审每一处串行假设，复杂度与正确性风险高，而基准证明瓶颈不在可并行化的位置。调用方批量已有完整入口（批量插入、按边键批量删除、批量删点带边），且批量数已含空表分组直写快路径。正确的优化方向是调用方批量，不是存储层并行。

**决策**。不引入顶点级锁或分片并行写，调用方优先批量。

**重启条件**。满足任一条方可重议：其一，在生产磁盘硬件上重跑该基准，落盘占比超六成；其二，画像证明表锁争用成为吞吐瓶颈。注意既有基准跑在临时目录上，生产磁盘的落盘占比会更高，换硬件后必须重跑再议，不可沿用本次数字直接决策。

## 4. 冻结单行回收入口：保留

**背景**。不可变形态的 `compact_row` 底层实现是全表 offsets 重建，单行回收即全表代价。曾考虑删除该入口，强制所有回收走批量或组级路径。

**现状**。生产路径已不存在逐行全表重建循环：分发层对冻结与映射的按顶点回收返回零并引导到批量与组级路径，边表写路径的冻结回收走批量收集后一次合并，刷盘整理的按行分支先判组是否冻结再路由，区域合并对冻结组直接走组级合并。`compact_row` 的剩余调用方是直接持有不可变形态的离线工具与单测。

**保留原因**。删除的收益为零（生产路径已不经过它），代价是破坏既有用例与离线单行工具入口。死代码清理针对的是无调用方的代码，该入口有真实调用方，不属于清理范围。保留不改变任何生产行为。

**决策**。保留 `compact_row` 作为离线与单行工具入口，不再作为清理任务。

**重启条件**。满足以下全部方可重议：不可变形态的直接持有路径被移除或全部迁移到批量接口，且离线工具给出替代入口。在此之前，任何以简化名义删除该入口的提议直接引用本文否决。
