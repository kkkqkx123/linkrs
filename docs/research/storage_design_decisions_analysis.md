# 存储设计决策差异分析

## 概述

本文档对比分析 Ladybug（ref/ladybug）与当前项目（linkrs）在存储架构上的设计理念差异。这些差异反映了不同的设计目标和权衡，而非简单的实现缺陷。

---

## 1. 节点组织：行组 vs 分片

| 方面 | Ladybug | 当前项目 |
|------|---------|----------|
| **结构** | NodeGroup → ChunkedNodeGroup → ColumnChunk → ColumnChunkData | ShardedVertexTable → VertexTable → ColumnStore → Column |
| **组织方式** | 固定大小行组（默认 2M 行） | 动态分片（基于 CPU 并行度，最多 256 分片） |
| **并发模型** | 行组级别并发 | 分片级别并发 |

**Ladybug 选择行组**：将数据按固定行数分组，行组作为压缩和刷盘的基本单元。适合大表的高效批量扫描，行组级别的压缩策略独立选择，读取时按行组粒度加载。

**当前项目选择分片**：通过 `fxhash(external_id) & (num_shards - 1)` 路由，每个分片独立的 `RwLock<VertexTable>`。适合高并发写入场景，多个写线程可无锁竞争地操作不同分片。

**设计理念差异**：Ladybug 面向读密集型 OLAP 场景优化批量扫描效率；当前项目面向写密集型场景优化并发写入吞吐。

---

## 2. 内部 ID 编码

| 方面 | Ladybug | 当前项目 |
|------|---------|----------|
| **类型** | `uint64_t` 全局唯一偏移量 | `u32` 内部 ID，编码为 `(segment << 12) \| slot` |
| **空间** | 8 字节 | 4 字节 |
| **限制** | 理论上支持 2^64 节点 | 每分片每段最多 4096 槽位，跨分片交织 |

**Ladybug 的 uint64_t**：简单直接的全局偏移量，无需槽位管理，适合超大规模数据。代价是每个 ID 占用 8 字节，在数十亿节点场景下 ID 空间本身消耗显著。

**当前项目的编码**：用 4 字节紧凑编码，通过分片交织保持全局唯一性。牺牲了单分片单段的容量上限换取内存效率，在中小规模数据（<10 亿节点）下是合理的空间换时间决策。

**设计理念差异**：Ladybug 优先考虑寻址简单性和大规模兼容性；当前项目优先考虑内存紧凑性和分片并发性。

---

## 3. 版本管理粒度

| 方面 | Ladybug | 当前项目 |
|------|---------|----------|
| **位置** | Vector 级别（VersionInfo） | Column 级别（每列维护 `row_start_ts` + `version_chains`） |
| **粒度** | 每个向量（默认 1024 行）一个版本记录 | 每行每列独立版本链 |
| **开销** | 低（向量化管理） | 高（每列维护 `VersionEntry { start_ts, end_ts, value }` 链表） |

**Ladybug 的 Vector 级版本**：批量管理版本，内存开销小。单行更新需标记整个向量，粒度较粗但适合高吞吐批量场景。

**当前项目的 Column 级版本**：细粒度控制，支持单行单列精确更新和时间旅行查询。代价是每个 Column 维护独立版本链，内存和 CPU 开销大。

**设计理念差异**：Ladybug 以吞吐量优先，版本管理批量化；当前项目以查询精度优先，支持细粒度的时间点读取。

## 4. CSR 实现策略

| 方面 | Ladybug | 当前项目 |
|------|---------|----------|
| **结构** | 标准 CSR：offset 数组 + length 数组 | 主块 + 溢出块：`MutableCsr` 两级设计 |
| **内存布局** | `offsets[v]` → `edges[start..start+length]` | 主块扁平数组 + overflow 块动态扩展 |
| **复杂度** | 低（标准实现） | 高（溢出块、OverflowIndex、SequentialRun 检测） |

**Ladybug 的标准 CSR**：简单高效，内存连续，缓存友好。但动态边添加需要重新组织整个 CSR 区域。

**当前项目的两级设计**：主块预分配固定槽位，溢出块动态扩展，避免频繁重分配。适合高频增量写入场景，但增加了实现复杂度和碎片化风险。

**设计理念差异**：Ladybug 追求读取路径的简洁和缓存友好；当前项目追求写入路径的高效增量扩展。

---

## 5. 边属性与拓扑的耦合度

| 方面 | Ladybug | 当前项目 |
|------|---------|----------|
| **CSR 条目** | 仅存边 ID（轻量级） | `Nbr` 结构体：endpoint + rank + edge_id + timestamp + prop_offset（32-40 字节） |
| **属性访问** | 通过 CSR 偏移直接访问属性列 | 通过 `prop_offset` 直接偏移访问 PropertyTable |
| **遍历语义** | 拓扑和属性完全分离 | 拓扑条目携带属性定位信息 |

**Ladybug 的分离设计**：CSR 仅存储轻量级边 ID，属性在独立列中按 CSR 偏移量直接寻址。遍历时只加载拓扑数据，属性读取延迟到需要时。

**当前项目的一体化设计**：Nbr 结构体携带 `prop_offset`，遍历时直接获取属性定位信息，省去二次查找。代价是每个边条目更大（32-40 字节 vs Ladybug 的边 ID 字段）。

**设计理念差异**：Ladybug 追求拓扑遍历的最小化加载；当前项目追求属性访问的零额外查找开销。

---

## 6. 边属性空间管理

| 方面 | Ladybug | 当前项目 |
|------|---------|----------|
| **策略** | 标记删除 + checkpoint 时重写 | `free_list` 立即回收 + `TieredTombstoneManager` 分层墓碑管理 |
| **复杂度** | 低 | 高 |
| **空间效率** | 低（删除后空间不立即释放） | 高（回收空闲槽位） |

**Ladybug 的简单策略**：删除操作仅标记，空间在 checkpoint 时通过重写释放。实现简单，但可能造成临时空间浪费。

**当前项目的回收机制**：`free_list` 立即回收空闲槽位供新边属性复用，`TieredTombstoneManager` 分热/冷层管理墓碑。空间效率高，适合长期运行场景。

**设计理念差异**：Ladybug 以实现简单性优先，空间回收延迟到批量操作；当前项目以空间效率优先，实时回收空闲资源。

---

## 7. 二级索引

| 方面 | Ladybug | 当前项目 |
|------|---------|----------|
| **索引** | 无专门机制，依赖列扫描 + 谓词下推 | `PropertyValueIndex`：`HashMap<prop_name, HashMap<encoded_value, HashSet<u32>>>` |
| **用途** | 列扫描 + Zone Map 过滤 | 支持属性值快速查找边 |

**Ladybug**：不提供属性值索引，依赖列扫描和谓词下推。对于 OLAP 场景，全表扫描 + Zone Map 过滤已足够高效。

**当前项目**：提供 `PropertyValueIndex`，支持按属性值精确查找边。增加了写入开销和内存使用，但为点查询提供了 O(1) 路径。

**设计理念差异**：Ladybug 面向分析型查询优化批量扫描；当前项目兼顾点查询和分析查询。

---

## 8. 磁盘格式与恢复

| 方面 | Ladybug | 当前项目 |
|------|---------|----------|
| **文件组织** | 每个表一个文件 | 每个分片/边类型多个文件（meta.bin, columns.bin 等） |
| **恢复机制** | WAL + ShadowFile（COW） | WAL + 原子重命名（shadow file） |
| **压缩** | 页级压缩 | zstd 页压缩 + 列级编码（Dictionary/RLE/BitPacking/ALP/FSST/Constant） |

**Ladybug 的单文件设计**：管理简单，原子性好，但文件可能很大，备份和恢复粒度粗。

**当前项目的多文件设计**：支持更细粒度的备份和恢复，每个分片/边类型独立持久化。增加了管理复杂度，但运维灵活性更好。

**设计理念差异**：Ladybug 追求文件管理的简单性；当前项目追求运维粒度的灵活性。

---

## 9. 总结

| 设计维度 | Ladybug 偏向 | 当前项目偏向 |
|----------|-------------|-------------|
| **读写模型** | 读密集（OLAP） | 写密集 + 点查询混合 |
| **并发策略** | 行组级并发 | 分片级并发 |
| **ID 空间** | 宽松（8 字节） | 紧凑（4 字节） |
| **版本管理** | 批量粗粒度 | 精确细粒度 |
| **CSR 设计** | 标准简洁 | 动态扩展 |
| **拓扑-属性关系** | 完全分离 | 携带定位信息 |
| **空间回收** | 延迟批量 | 实时回收 |
| **查询能力** | 扫描 + 谓词下推 | 扫描 + 二级索引 |
| **文件粒度** | 单文件 | 多文件 |

这些差异源于不同的应用目标：Ladybug 面向分析型图查询（大表扫描、批量处理），当前项目面向交互式图查询（高并发写入、点查询、时间旅行）。没有绝对优劣，需根据实际工作负载选择。
